## 한 줄 결론

**CapCut 에서 베낄 것은 효과 목록이 아니라 "효과를 다루는 방식"이다.**
효과가 타임라인에 **자기 띠로 얹혀서 위치와 길이를 사용자가 정하고, 세기를 슬라이더로
조절**한다는 것 — 이 한 가지가 핵심이다. 개별 효과 이름 수백 개는 유행을 타고 사라진다.

사용자 지시: **"효과 기능만 설계하고 사용자가 적용하도록 한다."** 이 문서의 선별안은
전부 그 원칙을 따른다. 어떤 효과도 "몇 초에 자동으로 들어간다"고 못 박지 않는다.

---

## 1. CapCut 은 "효과"를 여섯 갈래로 나눠 놓았다

한 덩어리가 아니다. 갈래마다 거는 곳도, 조절하는 법도 다르다.

| 갈래 | 무엇인가 | 어디에 붙나 |
|---|---|---|
| **Video Effects** (영상 효과) | 화면 전체를 바꾸는 것 — 흐림·빛번짐·왜곡·입자(비·눈·색종이) | **타임라인의 별도 띠** 또는 선택한 조각 |
| **Body Effects** (인물 효과) | 사람을 인식해 따라다니는 효과 | 사람이 잡힌 조각 |
| **Filters** (필터) | 색 프리셋 — 색조·채도·대비. **세기 슬라이더**가 붙는다 | 조각 또는 띠 |
| **Text Effects** (글자 효과) | 자막 자체의 꾸밈·움직임 | 글자 레이어 |
| **Transitions** (전환) | 장면이 바뀌는 이음매 | 두 조각 사이 |
| **AI Effects** | AI Stylize, Auto Velocity 등 | 그때그때 다름 |

여기에 "효과 탭"에는 없지만 **강조에 실제로 쓰이는 도구**가 따로 있다:

- **Masking (마스크)** — 도형(원·사각·띠)으로 화면 일부만 남기거나 지운다. 가장자리
  부드럽게(feather), 뒤집기(invert) 가능
- **Blur part of video / Blur background** — 화면 일부만 흐리게
- **Keyframe zoom** — 시간에 따라 화면을 당기거나 미는 것

> **판정**: 영상 편집에서 말하는 "강조"는 **효과 탭이 아니라 마스크·부분흐림·줌**으로
> 만들어진다. 우리도 그렇게 나눠야 한다.

## 2. 진짜 배울 점 — 워크플로 세 가지

### ① 효과는 "띠"다. 켜고 끄는 스위치가 아니다

CapCut 은 효과를 고르면 **타임라인 위에 막대 하나**가 생긴다. 그 막대를 좌우로 끌어
위치를 옮기고, 끝을 잡아당겨 길이를 바꾼다. 같은 효과를 **여러 개** 놓을 수도 있다.

이것이 사용자가 지시한 "**요소요소 작은 폭죽이 터지는**" 것을 만드는 유일한 방법이다.
폭죽 하나를 영상 전체에 거는 것이 아니라, **막대 여러 개를 원하는 시각에 놓는 것**이다.

우리 프로젝트에는 이미 **자막 타임라인 띠(F-25)** 가 있다. 같은 화면 부품을 재활용하면
새로 만들 것이 크게 줄어든다.

### ② 세기는 슬라이더로 준다

필터에는 세기 조절이 반드시 붙는다. 효과에도 조절 항목이 노출된다.
우리 조사에서 이미 확인한 바(`RESEARCH_screen_effects.md` 1절), **세기 3단계는 실제로
눈에 구별된다** — 화면의 3.2% / 13.3% / 31.2%.

단, 그때 얻은 교훈: **값 하나만 움직이면 단계가 안 벌어진다.** 개수와 진하기를 함께
움직여야 한다 (`memory/options-must-actually-differ.md`).

### ③ 갈래를 섞지 않는다

CapCut 이 "필터"와 "효과"를 굳이 갈라 놓은 이유가 있다. **색을 바꾸는 것**과 **없던 것을
그려 넣는 것**은 성격이 다르다. 색 보정은 즉시 계산되지만, 입자를 그리는 것은 화면을
픽셀 단위로 다시 만들어 **5.7배 느려진다**(실측).

→ 우리 화면도 **필터(색)** 와 **효과(입자·강조)** 를 갈라서 보여 주어야 한다.
사용자가 "왜 갑자기 느려졌지?"를 스스로 알 수 있어야 한다.

## 3. 우리 프로젝트의 현재 상태 (코드로 확인함)

| 항목 | 상태 | 확인 방법 |
|---|---|---|
| 화면비 자르기·여백 (crop/pad) | ✅ 있음 | `app/core/framing.py` |
| 자막 새기기 (ASS) | ✅ 있음 | `app/core/ffmpeg.py` 의 `burn_subtitles` |
| 자막 타임라인 띠 | ✅ 있음 | F-25, `USER_GUIDE.md` 206행 |
| 배경음악·덕킹 | ✅ 있음 | `app/core/audio_mix.py` |
| **색 보정 필터** (`eq` `hue` `curves`) | ❌ **하나도 없음** | 전체 검색 결과 0건 |
| **흐림·비네트·줌** (`boxblur` `vignette` `zoompan`) | ❌ **하나도 없음** | 전체 검색 결과 0건 |
| **프로젝트 저장 구조의 `effects` 항목** | ❌ **없음** | `app/core/projects.py` |
| **화면 확대(zoom) 값** | ❌ **없음** | `framing.py` 의 `DEFAULT_OUTPUT` 에 항목 자체가 없음 |

**백지 상태다.** 기존 기능을 뜯어고칠 걱정 없이 새로 얹으면 된다.
단 하나 예외가 **화면 확대**로, 이것은 `framing.py` 의 기존 계산을 손대야 한다.

## 4. 선별안 — 넣을 것

선별 기준 네 가지:

1. **정보 전달·숏폼 재제작에 실제로 쓰이는가** (유행 효과는 뺀다)
2. **FFmpeg 만으로 만들 수 있는가** (소재를 사 오지 않아도 되는가)
3. **사용자가 구간과 세기를 정할 수 있는가**
4. **결과가 눈에 확실히 구별되는가** (가짜 선택지를 만들지 않는가)

### A. 화면 효과 — 분위기·입자 (사용자 지시 항목 전부 포함)

| # | 효과 | 만드는 법 | 검증 상태 | 비고 |
|---|---|---|---|---|
| A1 | **비** | FFmpeg 필터만 | ✅ **실측 완료** — 빗줄기 15.4×1.6px | 세기 3단계 실측됨 |
| A2 | **눈** | FFmpeg 필터만 | ✅ **실측 완료** — 송이 9.7×9.6px | |
| A3 | **물방울 맺힘** | 파이썬이 굴절 지도 → `displace` | ✅ **실측 완료** — 안쪽 62% / 바깥 1.3% | 유리창에 맺힌 빗물. 흘러내리지는 않음 |
| A4 | **비눗방울 (거품 버블)** | 파이썬 입자 (폭죽과 같은 방식) | ❌ **미제작** | ✅ 사양 확정 — 아래 참조 |
| A5 | **작은 폭죽 (요소요소)** | 파이썬 입자 | ⚠️ **만들었으나 얇음** | 꼬리·번짐을 넣어야 폭죽다워짐 |

> ✅ **A3 과 A4 는 다른 것이고, 사용자가 원한 것은 A4 다** (2026-08-14 확정).
> 조사 때 만들어 데모 영상에 넣은 "물방울"은 **유리에 맺혀 화면을 휘게 하는 것**(A3, 굴절)이다.
> 사용자가 원한 것은 **떠다니는 비눗방울**(A4)이며 사양을 이렇게 못 박았다:
>
> - **천천히** 움직인다 (빠르게 흩날리지 않는다)
> - **이리저리** 떠다닌다 (곧게 떨어지지 않는다 — 좌우로 흔들리며 위아래로 표류)
> - **작아야 한다.** 크게 만들면 **화면을 가린다** ← 사용자가 직접 지적한 제약
>
> → 점검에 **크기 상한**을 넣는다. 방울 하나의 지름이 화면 짧은 변의 일정 비율(예: 4%)을
> 넘지 않는지, 그리고 방울이 덮는 전체 넓이가 화면의 일정 비율을 넘지 않는지 **픽셀로 잰다.**
> A3(맺힘)은 만들어 두었으므로 버리지 않고 **별도 효과로 함께 남긴다.**

### B. 화면 강조 — 어디를 보라고 가리키기

| # | 기능 | 만드는 법 | 판정 | 왜 필요한가 |
|---|---|---|---|---|
| B1 | **줌 강조 (확 당겼다 돌아오기)** | `scale`+`crop` 을 시간 함수로 | 가능 | 말의 강조점. **A~E 중 가장 많이 쓰인다** |
| B2 | **주변 어둡게 (스포트라이트)** | 어둡게 깐 화면 + 밝은 원형 마스크 합성 | 가능 | 한 곳만 보라고 할 때 |
| B3 | **부분 흐림** | `boxblur` + 마스크 | 가능 | 얼굴·개인정보 가리기. **실용성이 가장 높다** |
| B4 | **가장자리 어둡게 (비네트)** | FFmpeg `vignette` 내장 필터 | 가능 (가장 쌈) | 가운데로 시선 모으기 |
| B5 | **네모 테두리 표시** | `drawbox` 내장 필터 | 가능 (가장 쌈) | "여기 보세요" |

### C. 필터 — 색 보정

| # | 기능 | 만드는 법 | 판정 |
|---|---|---|---|
| C1 | **밝기·대비·채도 슬라이더** | `eq` 내장 필터 | 가능. 거의 공짜(속도 영향 없음) |
| C2 | **색감 프리셋 5종** (따뜻 / 차갑 / 선명 / 빈티지 / 흑백) | `eq`+`colorbalance`+`hue` 조합 | 가능 |

> C2 의 프리셋 이름은 **우리가 짓는다.** CapCut 의 이름을 가져오지 않는다
> (`CLAUDE.md` — 상표·자산 복제 금지).

## 5. 넣지 않을 것과 그 이유

| 뺀 것 | 이유 |
|---|---|
| **Body Effects (인물 추적)** | 사람을 인식하는 AI 모델이 따로 필요하다. 설치 파일이 수백 MB 커지고, 우리 목표(자막·나레이션)와 멀다 |
| **AI Stylize · Auto Velocity** | 외부 유료 서비스거나 큰 모델이 필요하다. 사용자가 요금을 내야 한다 |
| **글리치 · VHS · 네온 · 3D** | 유행 효과다. 정보 전달 영상에서는 **읽기를 방해한다**. 1~2년이면 촌스러워진다 |
| **장면 전환 효과 (Transitions)** | 영상 프로젝트는 조각을 이어붙이는 도구가 아니다. 사진 영상 쪽은 별도 판단 |
| **글자 효과** | 이미 **자막 프리셋 5종**이 있다 (`PRD.md` F-31). 중복이다 |
| **화살표 그리기** | 위치·방향·크기를 정하는 화면이 따로 필요해 비용이 크다. B5(네모 테두리)로 대부분 대체된다. **나중에 요청이 오면 그때** |

## 6. 화면 확대 — 강조와 한 몸이다

사용자가 따로 지시한 **영상 확대 조절**(인수인계 4-A절 ②)은 위 **B1(줌 강조)** 과
**계산이 같다.** 차이는 시간뿐이다.

- **화면 확대** = 영상 전체에 **고정 배율** (롱폼→숏폼 재제작용)
- **B1 줌 강조** = 특정 구간에서 **배율이 변한다**

→ **같은 계산 함수 하나**를 만들고, 배율을 고정으로 줄지 시간에 따라 줄지만 다르게 한다.
따로 만들면 두 곳이 어긋난다.

**실측된 제약**: 1280×720 을 세로 9:16 으로 자르면 이미 가로 화소의 32%만 쓴다.
여기서 1.6배 더 당기면 선명도가 **41% 떨어진다**. → **상한 2배**와 화면 경고가 필요하다.

**반드시 짝으로 고칠 곳** (`memory/preview-must-use-the-output-frame.md`):
`app/core/framing.py` 의 `resolve()` · `app/static/app.js` 의 `outputFrameRect()` ·
`tests/phase4_test.py` (240가지 대조). 한쪽만 고치면 미리보기와 결과물이 어긋난다.

## 7. 만드는 순서 제안

| 단계 | 무엇 | 왜 이 순서인가 |
|---|---|---|
| **1** | **효과 띠 구조 + 화면 확대 + 줌 강조(B1)** | 저장 구조와 타임라인 화면이라는 **뼈대**를 먼저 세운다. 확대는 사용자가 이미 두 번 요청했고 계산이 줌 강조와 같다 |
| **2** | **비(A1) · 눈(A2)** + 세기 3단계 | 이미 실측이 끝나 있다. 뼈대에 처음 얹는 효과로 가장 안전하다 |
| **3** | **필터(C1·C2)** | 속도 부담이 없고 만들기 쉽다. 사용자에게 즉시 보람이 있다 |
| **4** | **강조(B2 주변어둡게 · B3 부분흐림 · B4 비네트 · B5 테두리)** | 위치를 지정하는 화면이 필요해 앞의 셋보다 손이 간다 |
| **5** | **물방울(A3) · 비눗방울(A4) · 작은 폭죽(A5)** | 파이썬이 그림을 그려야 하고, 폭죽은 **보기 좋게 다듬는 데** 시간이 가장 많이 든다 |

각 단계에서 지킬 것 (조사 문서 7절과 동일):

1. **"그림이 나왔다"로 판정하지 않는다.** 효과 없는 영상을 한 번 더 만들어 픽셀을 대조한다
2. **세기 단계는 간격을 잰다.** 순서(약<보통<많이)와 최소 간격(1.3배)을 점검에 못 박는다
3. **효과를 켰을 때 자막이 살아 있는지** 매번 확인한다. 필터 순서가 바뀌면 조용히 사라진다
4. **미리보기는 브라우저에서 흉내 내지 않는다.** 이미 있는 10초 미리보기를 쓴다
   (5초 조각이 1~2초면 나온다 — 실측)

## 8. 아직 확인하지 않은 것 (정직하게)

- **사용자가 `화면효과_데모.mp4` 를 아직 보지 않았다.** 비·눈·물방울·폭죽이 **보기 좋은지**는
  사람만 판정할 수 있다. 이 판정 없이 4단계로 넘어가면 헛일이 될 수 있다
- **A4(떠다니는 비눗방울)는 아직 만들지 않았다.** 폭죽과 같은 입자 방식이면 될 것으로
  보이지만 **실측하지 않았다**
- **B1~B5 는 계산이 가능하다는 것까지만 판단했다.** 실제로 만들어 픽셀로 재지 않았다
