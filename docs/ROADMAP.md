2. **사용자가 직접 넣은 줄바꿈이 SRT에서 사라짐** — `text.split()`이 줄바꿈을 먹었다. 줄 단위로 먼저 나눈 뒤 각각 줄바꿈하도록 수정
3. **화면·SRT·번인의 줄바꿈 규칙이 제각각** — 세 곳 모두 같은 `wrap_text` 규칙을 쓰도록 통일. 화면이 넘치는 줄을 잘라내 감추던 것도 제거
4. **넛지 ±0.1초가 실제로는 0.1초 격자에 스냅** — 1.54초에서 ▶를 누르면 1.6초가 되던 것을 1.64초로
5. **타임라인은 노랑, 목록은 빨강** — 같은 기준에 다른 색이던 것 통일

남은 한계: 마우스로 하는 동작 3건은 브라우저 자동화가 없어 코드 검토로만 판정했다.

**목표**: 대본 → 나레이션 오디오 + 완벽 동기화 자막.

작업: F-40, F-41, F-42, F-43, F-44, F-51, F-52 (+ 자동 덕킹을 앞당겨 구현)

수용 기준 — `tests/phase2_test.py` 27개 항목 전부 통과:
- [x] 대본을 붙여넣고 나레이션을 생성하면 문장별 mp3와 이어붙인 전체 오디오가 생성된다
- [x] 자막 타이밍이 각 문장 오디오의 **실측 길이**로 산출되어 소리와 어긋나지 않는다
      — 자막 길이와 음성 길이의 차이 **최대 0.0ms**, 이어 붙이기 오차 **0.0ms**
      (120문장 스트레스 시험에서도 누적 오차 1.0ms)
- [x] 음성 미리듣기가 3초 내 재생된다 *(Phase 0에서 선행 구현)*
- [x] 한 문장만 고쳐 재생성하면 그 문장만 다시 만들어지고 이후 타이밍이 자동 재계산된다
      — 문장 하나를 길게 바꾸자 전체 끝이 18.48초 → 22.25초로 자동 이동
- [x] 자막을 대본으로 옮기는 버튼이 동작한다 (F-44)
- [x] 영상에 나레이션을 입힐 때 원본 소리 볼륨 조절이 반영된다 — 30% 설정이 결과에 반영됨
- [x] 나레이션 오디오 단독(mp3) 내보내기가 된다
- [x] edge-tts 호출 실패 시 프로그램이 죽지 않고 한국어 안내가 뜬다

설계상 중요한 결정:
- 자막 시각을 **계산값이 아니라 이어 붙인 결과 파일에서 각 문장이 실제로 시작하는 위치**로 확정한다.
  두 번 계산하지 않으므로 어긋날 여지가 없다.
- 문장을 이어 붙일 때 `concat` 방식 대신 **절대 위치 배치(adelay+amix)** 를 쓴다.
  mp3 인코더가 문장마다 넣는 미세한 여백이 뒤로 갈수록 누적되는 것을 막는다.
- `amix`에 `normalize=0` 을 준다. 이게 없으면 "원본 30%"가 실제로는 15%가 된다.
- 나레이션이 영상보다 길면 뒷부분이 잘리므로, 렌더링 전에 몇 초가 잘리는지 미리 경고한다.

독립 검증 결과 (별도 컨텍스트, 순환 논리를 깨는 방식으로 확인):
- 만들어진 나레이션 오디오를 **음성인식에 다시 통과시켜** 실제 발화 시각을 프로그램 바깥에서 구한 뒤
  저장된 자막 시각과 대조 — **누적 드리프트 없음** 확인 (첫 문장과 마지막 문장의 어긋남이 같음)
- 문장 재생성은 파일 수정시각·해시로 확인 — 해당 문장 파일만 바뀌고 나머지는 그대로
- 원본 볼륨 0%/30%/100%를 실제 음량으로 측정 — −38.1 / −32.9 / −23.9 dB (이론값과 일치)

검증에서 발견해 고친 결함:
1. **문장 사이 쉼이 설정값과 1.1초 어긋남** — edge-tts가 문장 앞에 0.2초, 뒤에 0.9초씩
   무음을 붙여 주는데 그것까지 '말하는 길이'로 세고 있었다. 음성 생성 직후 앞뒤 무음을
   잘라 내도록 수정. 실제 정적 1.42초 → **0.42초**, 자막과 소리의 어긋남 0.19초 → **0.06초**,
   같은 대본의 전체 길이 18.5초 → 13.5초 (죽은 공백 제거)
2. **잘림 경고가 내보내기 직전에 안 뜸** — 나레이션을 만든 직후에만 알려서, 나중에 다시 열어
   내보내면 잘리는 줄 모르고 진행됐다. 내보내기 대화상자를 열 때 다시 확인하고,
   영상으로 내보낼 때는 한 번 더 물어보도록 수정
3. **자체 테스트의 D1 검증이 동어반복이었음** — "자막 길이 == 음성 길이"는 자막 길이를
   음성 길이로 계산했으니 당연히 같다. 실제 오디오 파일에서 소리 나는 구간을 따로 재어
   자막 시각과 대조하도록 교체. F-44와 음성 생성 실패 처리 검사도 추가

재검증: `tests/phase2_test.py` **33개 항목** 통과 (전체 105개 항목 통과)

      — 눌렀을 때 디스크의 `updated_at`이 실제로 바뀌고 내용도 반영됨을 확인
- [x] 옛 프로젝트(`output` 키가 없는 것)도 그대로 열린다 — 기본값이 '원본 그대로'

설계상 중요한 결정:
- 화면비 계산은 `app/core/framing.py` 가 단일 출처다. 다만 **화면(`app.js`)도 같은 계산을
  갖고 있다** — 미리보기 틀은 마우스를 끄는 동안 즉시 다시 그려야 해서 서버에 물어볼 수
  없기 때문이다. 두 곳이 어긋나는 것을 막으려고 `tests/phase4_test.py`가 **`app.js` 파일을
  그대로 node로 실행해** 240가지 경우를 대조한다.
- 자르기 필터는 자막 필터보다 **먼저** 와야 하고, 자막 파일(ASS)은 **잘라낸 뒤의 크기**로
  만들어야 한다. 원본 크기로 만들면 글자 크기와 위치가 전부 어긋난다.
- 나레이션 영상은 화면비를 바꿀 때만 재인코딩한다. 바꾸지 않으면 지금까지처럼 화면을
  그대로 복사해 빠르다.

**검증 방식이 달라졌다**: 이번부터 브라우저 자동화(Playwright)로 **실제로 눌러서** 확인한다
(`tests/ui_test.py`, 33개 항목). Phase 1·3에 남아 있는 "코드 검토로만 판정" 항목들도
이 방식으로 옮길 수 있다. 자세한 방법은 `memory/verify-ui-by-actually-clicking.md`.

      | 약하게 | **약 70%** | threshold 0.08 · ratio 3 · release 250ms |

      **이름만 다른 가짜 선택지**가 되었다. `release`(놓아 주는 시간)를 함께 늘려야

#### 단계 1 — 사진이 들어올 통로를 연다 (0.5일)
- [x] 시작 화면 `[사진으로 시작]` 에서 파일 창에 **jpg·png·webp가 보이고** 여러 장을 한 번에 고를 수 있다
- [x] 사진 3장을 고른 뒤 `project.json` 의 `images` 에 경로 3개가 **순서대로** 들어 있다
- [x] **옛 프로젝트가 지금과 똑같이 열린다** (되돌아가기 확인)

#### 단계 2 — 사진을 영상으로 만든다 (자막 없이) (1일)
- [x] **크기가 제각각인 사진 30장(jpg·png 섞어서)**, 장당 3초로 내보내면 길이가 **90.0초 ± 0.1초**, 크기가 정확히 **1080×1920**
- [x] t=1초 · 46초 · 89초의 화면이 각각 **1번째 · 16번째 · 30번째 사진**과 같다
      — *조사 R-1의 **조용한 실패**(오류 없이 마지막 사진만 되풀이됨)를 잡는 검사다. **빼면 안 된다.***
- [x] 만드는 도중 `[취소]` 를 누르면 FFmpeg이 실제로 멈추고 반쪽짜리 파일이 남지 않는다
- [x] 진행률이 실제 진척에 따라 올라간다 (타이머 흉내가 아니다)

#### 단계 3 — 미리보기가 사진 프로젝트에서 동작한다 (1일)
- [x] 재생을 누르면 시간이 흐르고 그 시각의 사진이 미리보기에 바뀌어 나온다
- [x] 화면비를 9:16 → 16:9 → 1:1 로 바꾸면 **틀이 실제로 바뀌고** 잘릴 부분이 어둡게 보인다
- [x] **자막을 마우스로 끌 수 있고**, 끈 자리와 내보낸 영상의 자리가 같다 (글자 픽셀 무게중심 측정, 오차 1% 이내)
      — *`memory/preview-must-use-the-output-frame.md` 의 438픽셀 어긋남이 재발하는지 보는 검사*

#### 단계 4 — 사진 영상에 자막을 얹는다 (0.5일)
- [x] 사진 프로젝트에서 `[내보내기 → 자막 입힌 영상]` 이 **잠기지 않고** 동작한다
- [x] 만들어진 영상의 프레임에서 **한글이 네모(□)가 아니다**
- [x] 프로젝트 이름을 `사진, 시험;[a]'b` 로 지어도 성공한다 (`memory/ffmpeg-filter-path-escaping.md` 회귀 검사)

#### 단계 5 — 음원 영상 (1.5일)
- [x] mp3를 넣고 재생하면 **소리가 나고 시간이 흐른다**
- [x] **두드려 맞추기로 스페이스바를 눌러** 가사 3줄의 시작 시각을 찍을 수 있다 (실제로 눌러 확인)
- [x] 사진 3장을 가사 3줄에 짝지어 내보내면 영상 길이가 **음원 길이와 0.1초 이내**로 같다
- [x] **각 가사 줄이 시작되는 순간에 사진이 바뀐다** (가사 시작 +0.1초 지점의 프레임 색을 측정)
- [x] 사진 수와 가사 줄 수가 다를 때 무슨 일이 벌어지는지 **내보내기 전에 한국어로 알려 준다**

#### 단계 6 — 자막 강제정렬 (1.5일)
- [x] 샘플 영상의 **정확한 대본**을 붙여넣고 `[시간 붙이기]` 를 누르면 자막이 시각과 함께 만들어진다
- [x] 음성인식만으로 만든 자막과 견주어 **문장별 시작 시각 차이의 중앙값이 0.3초 이내**
- [x] **짝을 못 찾아 짐작한 줄이 화면에 표시되고**, 그 줄만 두드려 맞추기로 고칠 수 있다
- [x] 대본에 숫자("2024년")가 든 문장을 넣어도 죽지 않고 그 줄을 "짐작함"으로 표시한다

#### 단계 7 — 자막→대본 마무리 (0.25일)
- [x] `[자막을 대본으로]` 를 누르면 "나레이션을 만들면 지금 자막 시각이 새로 계산됩니다"를 **미리 알려 준다**
- [x] 목소리 교체 흐름에서 원본 소리 볼륨 기본값이 0%가 된다
- [x] `docs/PRD.md` 의 F-44 상태 표기를 실제(**이미 구현 완료**)에 맞게 고친다

## Phase 7 — 편집 편의 (사용자 요청) ✅ 완료 (2026-08-14)

Phase 6 이후 사용자가 실제로 화면을 써 보고 요청한 것들이다. 계획서에 없던 항목이므로
요청·판단·결과를 함께 남긴다.

### 1. 타임라인의 영상 띠 (필름스트립)

**요청**: "업로드한 영상 타임라인도 있어야 할 것 같아. CapCut 에는 창 아래부분에 영상
타임라인이 있었던 것 같아."

**판단**: 자막 시각을 **말소리**에 맞추는 일은 이미 있는 소리 파형이 더 정확하다
(화면은 그대로인데 말이 시작될 수 있고, 그건 파형에만 보인다). 다만 **장면이 바뀌는
순간**에 맞추거나 말이 없는 구간에 자막을 넣을 때는 화면이 보여야 한다. 그래서 넣었다.

**만든 방식**: 프레임을 낱장으로 뽑지 않고 **가로로 이어붙인 그림 한 장**으로 만든다.
FFmpeg 한 번, 요청 한 번으로 끝나고, 화면에서는 타임라인 폭에 맞춰 늘려 깔기만 하면
"이 자리 = 이 시각의 화면"이 저절로 맞는다. 파형과 똑같이 프로젝트 `cache/` 에 저장해
두 번째부터는 즉시 나온다 (`app/core/filmstrip.py`).

- 칸 수는 길이에 따라 40~300칸 (대략 2초에 한 칸). 위를 막는 이유는 그림이 너무 길어지면
  브라우저가 통째로 못 그리기 때문이다.
- 확대하면 늘어나 조금 흐려진다. 배율마다 다시 뽑으면 느려지므로 늘리는 쪽을 택했다.

**점검** `tests/filmstrip_test.py` 14개. **1초마다 색이 완전히 바뀌는 시험 영상**을 만들어,
띠의 자리를 잘라 색을 재서 "몇 초짜리 화면이 어느 자리에 있는지"를 20곳 대조한다.
`fps` 필터가 앞부분을 조용히 잘라먹는 사고를 이미 겪었기 때문에
(`memory/fps-filter-eats-the-first-images.md`), "그림이 나왔다"로는 판정하지 않는다.

### 2. 배경음악

**요청**: "MP3 오디오를 배경음으로 넣을수도 있고."

**판단**: 확인해 보니 **아예 없는 기능이었다.** mp3 는 사진 슬라이드쇼에서 "길이를 정하는
주인공"으로만 쓰이고, 영상 프로젝트에 음악을 까는 길이 없었다.

**만든 방식**: 자막은 `-vf`(화면 필터)로 새기는데 소리 섞기는 `-filter_complex` 가 필요하고
FFmpeg 은 **둘을 함께 쓰는 것을 거부한다.** 그래서 사진 영상에서 이미 검증한 '두 번에
나누기'를 그대로 썼다 — 자막을 새긴 뒤 그 결과에 음악을 얹는다. 이 단계는 화면을 다시
그리지 않으므로(`-c:v copy`) 값이 거의 들지 않는다 (`audio_mix.add_background_music`).

- 음악이 짧으면 **되풀이**하고 길면 **자른다**. 끝 2초는 서서히 줄인다.
- 소리 트랙이 없는 영상이면 음악만 얹는다 (`[0:a]` 를 쓰면 FFmpeg 이 거부한다).
- 역할이 정반대라 `audio_path`(주인공 음원)와 칸을 나눴다 → `bgm_path` · `bgm_volume`.

**점검** `tests/bgm_test.py` 18개. 음악을 **1500Hz 사인파**로 만들어, 원본(440Hz)과 주파수로
갈라서 잰다. 처음에는 880Hz 로 잡았다가 실패했는데 **880 은 440 의 2배음**이라 음악을
넣지 않아도 그 대역에 소리가 새어 나오기 때문이었다.

### 3. 덕킹 세기 3단계

**요청**: "덕킹세기 조절 가능하도록 수정."

**판단**: '몇 %'를 직접 받지 않았다. 압축기가 실제로 누르는 양은 **그 순간 나레이션이
얼마나 큰지**에 따라 달라져서, 30% 라고 적어 놓고 지키지 못한다. 대신 단계로 주고
각 단계의 **실측값**을 화면에 적었다 (약하게 70% · 보통 37% · 많이 22%).

처음에는 threshold·ratio 만 바꿨더니 '많이'가 '보통'보다 겨우 5%p 낮아 **이름만 다른
가짜 선택지**가 되었다. `release`(놓아 주는 시간)를 함께 늘려야 단어 사이에 원본이
되살아나지 않아 단계가 벌어진다는 것을 실측으로 확인했다.

### 4. 화면 손질 (사용자 지적)

| 지적 | 원인 | 처리 |
|---|---|---|
| 색 고르개가 온통 빨강 | 흰색·검정은 색상값이 없어 0(=빨강)으로 떨어졌다 | 색기가 없을 때 197도(앱의 '하늘' 견본과 같은 값)를 쓴다 |
| `시간 붙이기` 칸이 흰 상자 | 그 입력칸에만 **CSS 가 아예 없었다** | 다른 입력칸과 같은 `.script-input` 을 붙였다 |
| 화면비 단추 높이가 다름 | 안에 든 그림 높이가 15~26px 로 제각각 | 단추 높이를 76px 로 못 박았다 |
| 글자가 작다 | `style.css` 에 크기가 81곳 하드코딩 | 비율을 지키며 일률적으로 약 15% 키웠다 |
| 설명서가 안 굴러감 | `html` 이 막힌 채 `body` 만 풀려 있었다 | `memory/page-scroll-needs-html-not-body.md` 참고 |
| `?` 단추가 무슨 뜻인지 모름 | — | `사용설명서` 로 바꿨다 |
| `영상 모드`인데 사진으로 시작함 | 이름이 **소재**를 가리켜 헷갈렸다 | `자막 작업` · `나레이션 작업` (= 지금 무슨 일을 하는가) |

  넣었고, 통합은 하지 않았다.
