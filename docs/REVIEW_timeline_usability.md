## 0. 요약

자막 막대와 화면 효과 막대를 **끌어서 옮기고 양 끝을 끌어 늘이고 줄이는 기능은 v0.6.0 에 이미 있고, 브라우저에서 실제로 끌어 보니 동작한다.**
그런데도 "없다"는 의견이 나온 데는 이유가 있다. 처음 뜨는 안내창이 이 기능을 한 줄도 알려 주지 않고, 손잡이는 폭이 7픽셀이며, 타임라인은 화면 아래의 얇은 띠다.
그리고 끌고 나서 믿고 쓸 수 없는 결함이 셋 있다. 옆 자막과 겹쳐도 막지 않고, 붙지도 않고, 효과를 옮긴 뒤 Ctrl+Z 를 누르면 "되돌렸습니다"만 뜨고 아무것도 돌아오지 않는다.

**영상 자체를 끌어서 줄이는 것(앞뒤 잘라내기)은 없다.** 요구사항 문서가 "컷 편집"을 만들지 않는 것으로 정해 두었기 때문이다. 이것을 하려면 범위를 바꾸는 결정이 먼저 필요하다.

## 1. 어떻게 봤나, 무엇은 못 봤나

| 대상 | 방법 | 근거의 종류 |
|---|---|---|
| CapCut 9.2.0.3931 (이 컴퓨터에 설치된 것) | 프로그램 폴더 안의 한국어 화면 글자 번역표 `Resources/po/ko-KR.po` (글자 15,431개)에서 타임라인 조작 이름을 골라냈다 | 실제 배포 파일에서 읽음 |
| CapCut 프로젝트 저장 형식 | 사용자가 CapCut 으로 만든 프로젝트 7개 중 3개(`PLS 회사 소개 2ND`, `1219 (1)` 등)의 `draft_content.json` 을 읽기만 했다 | 실제 파일에서 읽음 |
| MovieFit Studio v0.6.0 | 코드를 읽고, 개발 서버를 띄워 시험용 사본 프로젝트에서 **진짜 마우스로 끌어 봤다** | 화면에서 직접 확인 |

못 본 것:

- **CapCut 이 끌기를 할 때 화면에서 어떻게 반응하는지는 직접 보지 못했다.** 역분석 도구(REA)의 "실행 중인 창 관찰" 기능이 맥 전용이라 윈도우에서 돌지 않는다. 그리고 CapCut 을 띄워 사용자 프로젝트를 열면 자동 저장으로 내용이 바뀔 수 있어 띄우지 않았다.
- CapCut 의 단축키가 어느 키에 배정됐는지는 확인하지 못했다. 배정표가 프로그램 안에 박혀 있고, 사용자 설정 파일(`Config/keymapSettings`)에는 "기본 배정표 사용" 한 줄뿐이다.
- 프로그램 내부 코드는 뜯어보지 않았다. 프로젝트 규칙대로 기능과 사용 흐름만 참고했다.

| 자막 나누기·합치기, 손으로 자막 넣기 | 자막 분할, 수동으로 캡션 입력 | 있음 |
| 자막 파일을 끌어다 놓아 타임라인에 넣기 | (SRT, LRC, ASS 지원) | 파일 고르기로 있음 |
| 단축키를 사람마다 바꾸기, 겹치면 경고 | 숏컷 충돌 | 없음 |

### 2-2. CapCut 이 조각의 시간을 적는 방식 (사용자 프로젝트에서)

영상·사진·소리 조각 하나마다 시간을 **두 개** 적는다. 단위는 백만분의 1초다.

- **타임라인 위 자리**: 결과 영상의 몇 초부터 얼마 동안 나오는가
- **원본에서 쓰는 부분**: 원본 파일의 몇 초부터 얼마만큼을 가져다 쓰는가

조각 끝을 끌어 줄이면 두 값만 바뀌고 원본 파일은 그대로다. 그래서 언제든 다시 늘일 수 있다.

실제 값 몇 개:

- `PLS 회사 소개 2ND`: 영상 줄 조각 11개 사이의 빈틈이 전부 0이다. 메인 트랙 마그넷이 켜져 있어서다(`maintrack_adsorb = True`).
- 같은 프로젝트에서 나레이션은 소리 줄에 **문장마다 따로 놓인 조각 10개**다. 하나씩 옮길 수 있다.
- 사진 조각의 원본 길이는 3시간으로 적혀 있다. 그래서 사진은 사실상 얼마든지 늘일 수 있다.
- 글자 조각(`1219 (1)`)에는 "타임라인 위 자리"만 있고 "원본에서 쓰는 부분"은 없다. 길이에 제한이 없다는 뜻이다.

## 3. MovieFit Studio 지금 상태 (2026-11-04, 개발 서버 8766, 시험 사본 프로젝트 `끌기시험`)

| 해 본 것 | 결과 |
|---|---|
| 2번 자막 오른쪽 끝을 마우스로 0.5초만큼 끌기 | **됨.** 끝 시각이 5.7초에서 6.2초로 바뀌고, 아래 목록 숫자와 되돌리기 단추도 따라 바뀜 |
| 같은 끝을 1초 더 끌어 3번 자막(6.25초 시작)과 겹치게 하기 | **막지 않음.** 7.2초까지 늘어나 3번 막대를 덮음. 경고도, 옆 자막 경계에 붙는 것도 없음 |
| 효과 막대("줌 강조" 3~6초)를 1초 뒤로 옮긴 뒤 Ctrl+Z | **결함.** "되돌렸습니다" 알림만 뜨고 효과는 4~7초 그대로. 되돌리기 기록에 자막과 글자 모양만 저장되기 때문이다(`app/static/app.js` 90·97·98줄) |
| 눈금 줄(00:00, 00:10…)의 20초 자리를 누르기 | **안 움직임.** 재생 위치 0초 그대로 |
| 자막 줄의 빈 곳(20초 부근) 누르기 | 됨. 20.3초로 이동 |
| 빨간 재생선을 잡아 끌기 | **안 됨.** 마우스를 받지 않게 막혀 있음 |
| Ctrl + 마우스 휠로 확대 | **안 됨.** 배율 그대로 |
| 손잡이 크기 | 폭 7픽셀. 마우스를 올리면 좌우 화살표로 바뀌기는 함 |
| 처음 쓰는 사람에게 뜨는 "편집기 사용법" 안내창 | 시간 조절은 ◀▶ 단추와 숫자 입력만 소개. **막대 끌기는 언급 없음** |
| 사용설명서 | 자막 장에 "막대를 마우스로 끌어서 옮길 수도 있습니다" 한 줄. **양 끝으로 길이 바꾸기는 자막 장에 없음** (효과 장에는 있음) |

코드로만 확인한 것 (화면에서 시험하지 않음):

- 타임라인에 **나레이션 줄과 배경음악 줄이 없다.** 배경음악은 영상 길이에 맞춰 저절로 반복되고 잘린다.
- **나레이션을 만든 뒤 자막 막대를 옮기면 소리는 따라오지 않는다.** 내보낼 때 미리 이어 붙인 나레이션 파일 하나를 쓰기 때문이다. 자막과 목소리가 어긋날 수 있다.
- 영상 앞뒤를 잘라내는 개념이 저장 데이터에 없다. 내보낼 때 영상 전체를 쓴다.
- 처음 설계 문서(`docs/UI_SPEC.md` 30줄)가 **"타임라인 드래그 대신 목록 편집"** 을 일부러 택했다. 지금 받은 의견은 이 방침과 정면으로 부딪친다.

### 묶음 A — 있는 기능을 보이게, 믿고 쓸 수 있게 (지금 범위 안, 작은 일)

| # | 고칠 것 | 왜 |
|---|---|---|
| A1 | 첫 안내창과 사용설명서 자막 장에 "막대를 끌어 옮기고, 양 끝을 끌어 길이를 바꾼다"를 넣는다 | 기능이 있는데 아무도 모른다. 이번 의견의 가장 유력한 원인 |
| A2 | 손잡이를 7픽셀에서 12~14픽셀로 넓히고, 막대에 마우스를 올리면 양 끝이 밝아지게 한다. 끄는 동안 "3.2초 → 6.2초 (3.0초)" 말풍선을 띄운다 | 잡을 자리가 보여야 잡는다. 숫자가 보여야 정확히 놓는다 |
| A3 | 붙기와 겹침 막기: 옆 자막 경계·재생선·효과 경계에 가까워지면 착 붙고, 옆 자막을 넘어가려 하면 경계에서 멈춘다. Alt 를 누른 채 끌면 붙기를 끈다 | CapCut 의 "자동 스냅"에 해당. 지금은 겹쳐도 아무 표시가 없다 |
| A4 | 되돌리기 결함 수정: 효과·화면비·틀 바꾼 것까지 되돌리기 기록에 넣는다 | 지금은 "되돌렸습니다"라고 하고 아무것도 안 돌아온다. 사용자를 속이는 상태 |
| A5 | 눈금 줄을 누르거나 끌면 재생 위치가 따라오고, 빨간 재생선을 잡아 끌 수 있게 한다 | 영상 편집기를 써 본 사람이 가장 먼저 하는 동작 |
| A6 | Ctrl + 휠로 확대·축소, 타임라인 위 경계를 끌어 높이 조절 | 막대가 작으면 끌기도 어렵다 |

|---|---|---|

## 5. 추천 순서

1. **A 묶음 전부 → 지인에게 다시 써 보게 하기.** 의견의 상당 부분이 "있는데 몰랐다"와 "끌고 나서 믿을 수 없다"에서 나왔을 가능성이 크다. 다시 받아 보는 의견이 B·C 중 무엇을 먼저 할지 정해 준다
2. 그다음 B1(나레이션 줄). 대본 모드가 이 프로그램의 핵심 기능인데, 지금은 자막을 옮기면 목소리와 어긋날 수 있다
3. C1(영상 앞뒤 다듬기)은 범위를 바꿀지 결정한 다음에

`docs/UI_SPEC.md` 의 "타임라인 드래그 대신 목록 편집" 방침은 "목록 편집과 타임라인 끌기 둘 다"로 고쳐 적어야 한다. 목록 편집의 장점은 그대로 남는다.
