## 한 줄 결론

**"통짜 음성복제 TTS 엔진"을 새로 넣지 말고, 지금 쓰는 edge-tts가 만든 한국어 음성에 OpenVoice v2의 "음색 변환기(ToneColorConverter, 131MB)"만 얹어서 사용자 목소리로 바꾸는 방식을 권장한다.** 이유는 셋이다 — ① 코드와 모델 가중치가 **둘 다 MIT**라 유튜브 수익화에 걸림돌이 없고, ② 한국어 발음·억양은 이미 검증된 edge-tts가 그대로 담당하므로 "한국어가 어색하다"는 위험 자체가 사라지며, ③ 추가 다운로드가 약 **0.4GB 수준**이고 변환 모델이 작아 CPU에서도 감당된다. 반대로, 라이선스가 가장 깨끗하고 관리도 활발한 유일한 통짜 후보였던 **Chatterbox는 제작사(Resemble AI)가 스스로 "한국어는 상용 배포에 쓰지 말라"고 공식 문서에 적어 두어** 탈락했다.

> 용어: **음색 변환(voice conversion)** = 말의 내용·속도·억양은 그대로 두고 "목소리의 음색(누구 목소리처럼 들리는가)"만 바꾸는 기술. **제로샷 복제(zero-shot cloning)** = 사용자 목소리로 별도 학습(훈련) 없이, 짧은 샘플 몇 초만 듣고 바로 흉내내는 기술.

## 추천안 상세 — edge-tts + OpenVoice v2 음색 변환기

### 어떤 구조인가

```
사용자 대본 ──▶ edge-tts(ko-KR-SunHiNeural) ──▶ 한국어 음성 wav
                                                     │
사용자 목소리 샘플 20~30초 ──▶ 음색 임베딩 추출 ────┐  │
                                                  ▼  ▼
                                    OpenVoice ToneColorConverter
                                                  │
                                                  ▼
                                   "내 목소리로 말하는" 나레이션 wav
```

핵심은 **음성을 새로 만들지 않고, 이미 만들어진 음성의 음색만 갈아끼운다**는 점이다.

### 왜 이 방식이 이기는가

1. **라이선스가 완전히 깨끗하다 (가장 중요한 축).**
   - 코드: `myshell-ai/OpenVoice`의 LICENSE 파일 전문을 확인했다 — 표준 MIT 텍스트다.
   - 가중치: Hugging Face `myshell-ai/OpenVoiceV2` 모델 카드의 라이선스 필드가 `mit`이고, README에도 "2024년 4월부터 V1·V2 모두 MIT 라이선스. 상업적 사용 무료"라고 명시돼 있다.
   - 즉 **코드와 가중치가 모두 MIT**다. 이 조건을 만족하면서 한국어가 실제로 쓸 만한 후보는 사실상 이것뿐이었다.

2. **한국어 품질 위험이 0이다.**
   다른 모든 후보는 "그 모델이 한국어를 얼마나 잘하느냐"가 도박이다. 이 방식은 발음·억양·띄어읽기를 전부 edge-tts가 처리하고, 변환기는 음색만 건드린다. 이미 프로젝트에서 검증한 한국어 품질이 그대로 유지된다.

3. **기존 설계와 충돌이 없다.**
   `docs/TECH_SPEC.md` 5장의 타이밍 계산은 문장별 오디오 길이(duration)에 의존한다. 음색 변환은 **입력과 출력의 길이가 동일하다.** 반면 통짜 제로샷 TTS는 매번 길이가 달라지고, 문장을 반복하거나 없는 말을 지어내는 환각(hallucination)이 발생할 수 있다(Chatterbox v3의 개선 항목에 "환각 감소"가 들어 있다는 것 자체가 이 문제가 실재한다는 증거다). 길이가 보존되면 자막 싱크가 흔들리지 않는다.

4. **의존성이 놀랄 만큼 가볍다.**
   실제 추론 코드(`openvoice/api.py`)를 읽어 확인했다. `ToneColorConverter`가 import 하는 것은 `torch`, `numpy`, `soundfile`, `librosa`와 같은 저장소 내부 모듈 4개뿐이다. 저장소의 `requirements.txt`에 있는 지뢰들(`numpy==1.22.0`, `gradio==3.48.0`, `whisper-timestamped` 등)은 **음색 변환 경로에는 전혀 필요 없다.**
   또한 `convert()` 안의 워터마크 삽입은 `add_watermark()`가 `watermark_model is None`이면 원본을 그대로 돌려주도록 되어 있어, `wavmark` 패키지 없이도 정상 동작한다.
   저장소 기본 안내가 요구하는 `se_extractor`(whisper-timestamped 필요)도 우회할 수 있다 — `ToneColorConverter.extract_se(wav 파일 목록)`을 직접 부르면 되고, 이건 `librosa`와 `torch`만 쓴다.

### 사용자가 치르는 비용 (솔직하게)

| 항목 | 실제 수치 |
|---|---|
| 추가 다운로드 | PyTorch(CPU, Windows, Python 3.11) 휠 **204MB** + 변환 모델 **131MB** + librosa/soundfile/numba 등 부속 약 100MB ⇒ **총 약 0.4GB** |
| 디스크 점유 | 압축이 풀리면 **약 1.5~2GB** (대부분 PyTorch의 DLL) |
| 최초 실행 대기 | 인터넷 100Mbps 기준 다운로드 약 1~2분 + 설치 1~3분. 모델 로딩은 최초 1회 수 초 |
| 문장당 처리 시간 | ⚠️ **실측하지 않았다.** 모델이 131MB의 비자기회귀 구조라 실시간보다 빠를 것으로 보이지만, 1차 구현 후 `tests/sample/`로 반드시 측정해야 한다 |
| 사용자 목소리 샘플 | **20~30초, 조용한 곳에서, 배경음악 없이** 권장. 공식 문서가 최소 길이를 숫자로 명시하지 않아 안전한 값으로 잡았다 |

### 이 방식의 진짜 한계 (반드시 UI에 적을 것)

**음색만 바뀌고 말투는 안 바뀐다.** 결과물은 "내 목소리의 성대로 edge-tts가 말하는 느낌"이다. 사용자의 특유한 억양, 말버릇, 감정 표현은 재현되지 않는다. 완전한 성대모사를 기대하는 사용자는 실망할 수 있으므로, UI에서 **"목소리 톤(음색)을 바꿉니다 — 말투와 속도는 선택한 기본 음성을 따릅니다"**라고 처음부터 정확히 알려야 한다. 반대로 이 성질은 나레이션 용도에서는 장점이다(길이 예측 가능, 발음 안정).

## 차선책과 전환 조건

### 차선책 1 — Chatterbox Multilingual (조건부 대기)

라이선스(코드 MIT + 가중치 MIT), 관리 상태(2026-07-21 커밋, 26k★, HF 다운로드 206만), `pip install chatterbox-tts` 한 줄 설치, Python 3.10 이상 지원 — 모든 축에서 최고다. **오직 한국어 품질 하나 때문에 탈락했다.**

제작사 Resemble AI가 2026년 6월 10일 v3 발표 글의 "v3가 아직 못 하는 것" 절에 직접 이렇게 썼다:

> "한국어와 베트남어는 상용 품질이 아니다. v3는 한국어와 베트남어를 각각 CER 70.90%, 75.21%로 생성하며, 이는 그다음으로 약한 언어보다 한 자릿수 이상 나쁘다. (…) **개선판을 내놓기 전까지는 두 언어의 상용 배포에 v3를 쓰지 말 것을 권한다.**"

(CER = 문자 오류율. 70%면 글자 열 개 중 일곱 개가 틀리게 발음된다는 뜻으로, 사실상 못 알아듣는 수준이다.)

**전환 조건:** Resemble AI가 예고한 **"한국어 Single-Language Pack" 또는 한국어가 개선된 멀티링구얼 체크포인트를 실제로 출시**하고, 우리가 샘플로 직접 들어 확인했을 때. 같은 글에서 후속으로 내겠다고 명시했으므로 분기마다 한 번씩 확인할 가치가 있다. 그때는 통짜 제로샷 복제(말투까지 복제)로 갈아탈 수 있다. 단 그 경우 다운로드가 3.4GB로 뛰고, CPU 속도를 반드시 재측정해야 한다(0.5B 자기회귀 모델이라 CPU에서 실시간의 수 배 느릴 가능성이 높다. CPU용으로 나온 Nano 모델은 영어 전용이라 우리에겐 해당 없음).

### 차선책 2 — GPT-SoVITS (품질 최우선 사용자용, 앱 내 통합은 비권장)

MIT 코드 + MIT 가중치, 한국어 공식 지원, 5초 제로샷 / 1분 파인튜닝, 60.7k★로 이 분야에서 가장 활발하다. 음성 유사도는 후보 중 최상급이다.
그러나 **우리 앱에 넣기에는 부적합하다**: 가중치 5.3GB, Windows 설치가 conda + PowerShell 스크립트이거나 별도 7z 통합 패키지 다운로드이고, CPU는 Python 3.9 / PyTorch 2.2.2 조합으로만 테스트되었다고 README가 밝히고 있다. 우리 앱의 가상환경에 `pip`로 얹을 수 있는 물건이 아니다.

**전환 조건:** 사용자들이 "말투까지 진짜 내 목소리"를 강하게 요구하고, GPU 보유 사용자로 대상을 좁히는 것을 받아들일 때. 그때도 앱 내 통합보다는 "GPT-SoVITS로 만든 wav 파일을 가져오기" 형태의 연동이 현실적이다.

## 탈락한 것들과 탈락 이유 (한 줄씩)

- **Coqui XTTS-v2** — 가중치가 CPML 라이선스이고, 그 전문을 직접 확인하니 "**모델과 그 출력물의 비상업적 사용만 허용**"이며 "수익 창출 활동에 쓰는 것은 비상업 목적이 아니다"라고 못 박혀 있다. 유튜브 수익화 사용자에게는 명백한 위반이고, 회사가 2024년 1월 폐업해 **상업용 라이선스를 사줄 상대조차 없다.**
- **F5-TTS** — 코드는 MIT지만 사전학습 가중치가 학습 데이터(Emilia) 때문에 CC-BY-NC(비상업)다. README에 저자들이 직접 명시했다. 게다가 공식 한국어 지원도 없다.
- **Fish Speech / OpenAudio S2** — 코드와 가중치 **둘 다** "Fish Audio Research License"(연구용)로, README에 "위반 시 조치하겠다"고까지 적혀 있다.
- **CosyVoice 2** — 라이선스(Apache-2.0)와 한국어 지원은 합격이지만, `requirements.txt`가 `torch==2.3.1`을 CUDA 12.1 인덱스와 함께 강제하고 Matcha-TTS 서브모듈까지 필요해 비개발자의 `pip install`로는 설치가 불가능에 가깝다. 가중치도 4.9GB다.
- **Supertonic 3** — CPU 속도(99M, ONNX)와 한국어 지원은 이 목록에서 최고였으나, 저장소가 **2026-07-23자로 아카이브 예고**되었고 음성 복제에 필요한 Voice Builder가 **2026-08-31에 종료**된다. 게다가 공개된 저장소 자체에는 로컬 음성복제 파이프라인이 아예 없다("고정 음성 TTS만 제공"이라고 README가 명시).
- **Higgs Audio v2** — 단일 모델 파일이 11.5GB(3B 파라미터)로 CPU 노트북에서는 논외.
- **VibeVoice 1.5B** — MIT에 5만 스타지만 지원 언어가 영어·중국어뿐이다.
- **Zonos v0.1** — 2025년 3월 이후 개발이 멈췄고, eSpeak-ng라는 별도 프로그램 설치가 필요하며 Windows는 제3자 포크로만 돌아간다. 한국어 지원도 확인되지 않았다.
- **IndexTTS-2.5** — 최신 버전 지원 언어가 중·영·일·스페인·아랍어로, **한국어가 없다.** 라이선스도 표준 SPDX로 식별되지 않는다(NOASSERTION).
- **Spark-TTS** — 2025년 4월 이후 개발 정지, 중국어·영어 중심.
- **Piper** — 애초에 제로샷 복제가 아니라 **음성마다 별도 학습(파인튜닝)이 필요**해서 "샘플 녹음하고 바로 사용" 요구사항에 맞지 않는다. 덤으로, 원 저장소 `rhasspy/piper`는 아카이브되었고 후속 저장소 `OHF-Voice/piper1-gpl`은 이름 그대로 **GPL-3.0으로 라이선스가 바뀌었다** — MIT 프로젝트에 결합하면 라이선스 오염 문제가 생기므로 나중에 다른 용도로도 가져다 쓰지 말 것.
- **seed-vc** (음색변환 대안으로 검토) — 저장소 아카이브 완료 + GPL-3.0이라 탈락.

## 통합 설계 제안

### 1. 어댑터 뒤에 어떻게 끼우는가 — "엔진 추가"가 아니라 "후처리 데코레이터"

`docs/TECH_SPEC.md` 3장 R1이 정한 인터페이스는 그대로 둔다:

```
TTSEngine.synthesize(text, voice, rate) -> (wav_bytes, duration)
```

권장안은 이 인터페이스를 **감싸는(wrapping)** 형태다. 새 엔진을 만드는 게 아니라 기존 엔진의 출력을 한 번 더 가공하므로, 인터페이스를 바꿀 필요가 전혀 없다.

```
app/core/tts/
├─ base.py          # 기존 TTSEngine 인터페이스 (수정 없음)
├─ edge.py          # 기존 EdgeTTS 구현 (수정 없음)
└─ voice_clone.py   # 신규: ClonedVoiceEngine(TTSEngine)
                    #   - 내부에 EdgeTTS 인스턴스를 하나 들고 있음
                    #   - synthesize() 호출 시:
                    #       1) inner.synthesize()로 한국어 wav 생성
                    #       2) ToneColorConverter로 음색 교체
                    #       3) (wav_bytes, duration) 반환 — duration은 1)과 동일
```

- `voice` 인자에 `clone:{프로필ID}` 같은 접두사를 쓰면 라우팅이 단순해진다. 예: `ko-KR-SunHiNeural` → 기존 경로, `clone:myvoice1` → 복제 경로.
- 사용자 음색 임베딩(`.pth`, 수 KB)은 `projects/` 밖의 공용 위치(예: `voices/{프로필ID}/se.pth`)에 저장한다. 프로젝트마다 다시 녹음하게 만들면 안 된다.
- edge-tts 각 음성의 **원본 음색 임베딩(src_se)**은 최초 1회 계산해 캐시한다. 매번 계산할 필요가 없다.
- OpenVoice의 추론 파일 4개(`api.py`, `models.py`, `mel_processing.py`, `commons.py` 및 부속)는 **저장소가 정체 상태이므로 `app/vendor/openvoice/`에 동봉**한다. MIT가 허용하며, 원저작권 고지를 함께 넣는다. 이렇게 하면 원 저장소의 깨진 버전 핀(`numpy==1.22.0` 등)에 영향받지 않는다.
- 외부 프로그램 호출 규칙(CLAUDE.md)에 따라 FFmpeg 호출은 기존 `app/core/ffmpeg.py`를 그대로 쓰고, 새 subprocess를 만들지 않는다. 샘플 녹음의 wav 변환·리샘플링도 여기서 처리한다.

### 2. 선택 설치로 갈 것 — `requirements-voice.txt` 분리 (강력 권장)

**PyTorch를 기본 의존성으로 만들면 안 된다.** 이유:

- 현재 STT에 쓰는 `faster-whisper`는 CTranslate2 기반이라 **PyTorch가 필요 없다.** 즉 지금 이 프로젝트에는 torch가 없다.
- torch를 `requirements.txt`에 넣는 순간 이 기능을 쓸 생각이 없는 모든 사용자의 최초 설치가 **204MB 다운로드 / 1.5GB 디스크**만큼 무거워진다. 비개발자에게 첫 설치 실패는 곧 이탈이다.

따라서:

```
requirements.txt          # 기존 그대로 (torch 없음)
requirements-voice.txt    # torch, torchaudio, librosa, soundfile  ← 선택
```

설치 트리거는 사용자가 "내 목소리 등록" 화면에 처음 들어와 **[설치하고 계속하기]를 누른 시점**으로 한다. `tools/check_env.py`에도 이 선택 구성요소의 설치 여부를 표시하는 항목을 추가한다. 설치는 백그라운드 작업(job)으로 돌리고 진행률을 폴링한다 — TECH_SPEC 3장 R3의 원칙과 동일하다.

### 3. 다운로드 전에 UI가 반드시 말해야 할 것

설치 버튼 위에 다음 네 가지를 **숫자로** 보여준다. "잠시만 기다려 주세요" 같은 문구는 금지다.

1. **"약 400MB를 내려받고, 디스크 약 2GB를 사용합니다."**
2. **"인터넷 속도에 따라 2~5분 걸립니다. 한 번만 설치하면 다음부터는 바로 사용됩니다."**
3. **"설치 중에도 자막 편집 등 다른 작업은 계속할 수 있습니다."** (백그라운드 작업이므로)
4. **"목소리 톤(음색)을 내 목소리로 바꿉니다. 말투와 말하는 속도는 선택한 기본 음성을 따릅니다."** ← 앞서 말한 한계의 사전 고지

그리고 녹음 화면에는:

5. **"조용한 곳에서 20~30초 정도, 배경음악 없이 또렷하게 읽어 주세요."** + 읽을 예시 문장 제공
6. 첫 변환 결과를 **짧은 미리듣기 한 문장으로 먼저 들려주고** 사용자가 "이 목소리로 진행" / "다시 녹음"을 고르게 한다. 전체 나레이션을 다 만든 뒤에 마음에 안 든다고 하면 시간 낭비가 크다.

## 윤리·법적 주의

이 기능은 **사용자 본인의 목소리**를 등록해 자기 나레이션을 만드는 용도로 설계·안내되어야 한다. 사실관계만 정리하면:

- 타인의 목소리를 동의 없이 복제해 공개하는 것은 국가에 따라 초상권·퍼블리시티권·개인정보 문제를 일으킬 수 있다. 특히 **한국은 2024년 시행된 이른바 딥페이크 관련 규제 흐름과 선거법상 딥페이크 규정이 있고**, EU는 AI Act 제50조로 AI 생성 콘텐츠의 고지 의무를 도입했다. (⚠️ 이 문단의 법령 세부 내용은 이번 조사에서 1차 출처로 확인하지 않았다 — 아래 "검증 안 된 것" 참조. UI 문구에는 구체적 법 조문을 쓰지 말고 일반적 주의만 적을 것.)
- 우리 앱은 로컬에서만 동작하고 녹음 파일을 외부로 보내지 않으므로, **"녹음은 내 컴퓨터에만 저장되며 어디로도 전송되지 않습니다"**라고 명시할 수 있다. 이건 사실이고, 사용자에게 중요한 안심 요소다.

**UI에 넣을 문구 (권장 원문):**

> **본인 목소리만 등록해 주세요.**
> 이 기능은 사용자 본인의 목소리로 나레이션을 만들기 위한 것입니다. 다른 사람의 목소리를 동의 없이 등록해 사용하면 법적 문제가 발생할 수 있으며, 그에 대한 책임은 사용자에게 있습니다.
> 녹음 파일과 음성 정보는 이 컴퓨터에만 저장되며 인터넷으로 전송되지 않습니다. [등록한 목소리 삭제]

추가로 **[등록한 목소리 삭제]** 버튼을 반드시 제공한다(녹음 원본 + 임베딩 파일 모두 삭제). 생체정보성 데이터를 만들어 놓고 지울 방법을 안 주는 것은 그 자체로 문제다.

참고로 탈락한 Chatterbox는 모든 출력에 PerTh 신경망 워터마크를 기본 삽입한다. 우리가 채택한 OpenVoice 경로는 워터마크가 **선택**이며, 기본값에서는 `wavmark` 모델이 없으면 삽입되지 않는다. 향후 출처 표시 의무가 강화되면 이 부분을 켜는 것을 검토할 수 있다.

## 검증 안 된 것

1차 출처로 확인하지 못한 항목이다. 구현 전/중에 실측하거나 별도로 확인해야 한다.

1. **OpenVoice 음색 변환기의 실제 CPU 속도.** 공개된 벤치마크를 찾지 못했다. 모델 크기(131MB)와 비자기회귀 구조로부터 "빠를 것"이라 추론했을 뿐이다. → **1차 구현 직후 `tests/sample/`의 10초 한국어 문장으로 실측할 것.** 만약 실시간의 2배보다 느리면 추천을 재검토해야 한다.
2. **edge-tts → OpenVoice 변환 결과의 실제 한국어 품질과 유사도.** 아무도 대신 들어줄 수 없다. 사용자 목소리 샘플로 직접 만들어 들어봐야 한다. 특히 변환 후 음질 저하(먹먹함, 금속성 잡음)가 있는지 확인 필요.
3. **OpenVoice V2가 요구하는 참조 음성의 최소 길이.** 공식 문서에 숫자가 없다. 메모의 "20~30초"는 다른 엔진들의 관행(XTTS 6초, Chatterbox 예제 10초, Zonos 10~30초)에서 잡은 안전값이다.
4. **Chatterbox Multilingual(0.5B)의 CPU 실시간 배수.** README의 "8코어에서 실시간 3배"는 **영어 전용 Nano(110M) 모델 수치**이며, 멀티링구얼 모델의 CPU 수치는 공개되지 않았다.
5. **MeloTTS가 Windows + Python 3.11에서 설치되는지.** PyPI 패키지(0.1.1, 2024-02-29)는 `torch<2.0`을 강제하는데 이 조합은 Python 3.11 휠이 없다. GitHub 버전은 다를 수 있으나, 공식 문서 자체가 "Windows 사용자는 Docker를 권장"한다. 추천안은 MeloTTS를 쓰지 않으므로 이 리스크를 회피하지만, 만약 MeloTTS 경로로 선회한다면 반드시 먼저 검증해야 한다.
6. **CosyVoice 2의 Windows 설치 가능 여부.** `requirements.txt`의 CUDA 인덱스 강제와 서브모듈 요구만 보고 "사실상 불가"로 판단했을 뿐, 실제로 시도해 보지는 않았다.
7. **한국·EU의 AI 음성 관련 구체적 법령 내용.** 위 윤리 절의 법령 언급은 이번 조사에서 1차 출처(법령 원문)로 확인하지 않았다. UI 문구는 구체 조문 인용 없이 일반적 주의 수준으로 유지할 것.
8. **`lj1995/GPT-SoVITS` 가중치 저장소 안에 포함된 제3자 모델들(chinese-hubert, chinese-roberta, BigVGAN)의 개별 라이선스.** 저장소 카드 전체는 MIT로 표시되나 하위 구성요소별로는 확인하지 않았다.
9. **Chatterbox의 PerTh 워터마크가 유튜브 수익화·저작권 시스템에 미치는 영향.** 문제될 이유가 없어 보이지만 확인하지 않았다.
