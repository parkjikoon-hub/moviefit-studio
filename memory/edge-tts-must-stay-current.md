edge-tts(무료 나레이션 음성 부품)는 **마이크로소프트가 접속 규칙을 바꾸면 옛 판이 403 으로 통째로 막힌다.** 배포한 지 몇 달 지나면 나레이션이 조용히 죽어 있을 수 있다. 오류 이름은 `WSServerHandshakeError` 이고, 화면에는 "인터넷 연결을 확인하세요"로 나온다.

무슨 일이 있었나 (2026-11-04):
타임라인 작업 뒤 전체 점검을 돌렸더니 나레이션을 만드는 점검 넷(phase2·ducking·phase4·voice_language)이
같은 오류로 실패했다. 인터넷은 멀쩡했다. 직접 불러 보니:

    7.2.8 (설치된 것, v0.6.0 설치 파일에도 이 판)  → 403 Invalid response status
    7.3.1 (그때 최신, 임시 폴더에 따로 받아 시험)  → 성공

즉 **v0.6.0 을 받은 모든 사람이 그 시점부터 나레이션을 못 만든다.** 이 프로그램의 핵심 기능이다.

고친 것: `requirements.txt` 를 `edge-tts>=7.3.1` 로 올리고 개발 환경을 7.3.1 로 올렸다.
설치본은 **새 설치 파일을 만들어 배포해야** 고쳐진다. 설치본에는 pip 이 없다 ([[installed-app-needs-restart]]).

진단할 때는 개발 환경을 건드리지 말고 `pip install --no-deps --target <임시폴더> edge-tts==<새판>` 으로 따로 받아 시험한다.

## 거절 번호를 먼저 본다 — 403 과 503 은 전혀 다른 일이다 (2026-11-04, v0.7.0 배포 전)

같은 날 오후 전체 점검에서 덕킹 점검이 **다시** `WSServerHandshakeError` 로 죽었다. 7.3.1 로 올린 뒤였다.
서버 기록의 번호를 보니 **503** 이었고, 직후에 직접 부르니 성공했다. 같은 시간대에 미리듣기도
두 번 더 이따금 실패했다 — 마이크로소프트 서버가 그날 가끔 바빴던 것이다.

    403  부품 판이 낡아 막힘     → 다시 물어도 소용없다. 새 판을 배포해야 한다
    503  서버가 잠시 바쁨        → 1~2초 뒤 다시 물으면 된다

번호는 서버 기록(`dev_server.log`)의 `WSServerHandshakeError: 503, message=...` 에 있다.
오류 이름만 보고 "또 판이 낡았다"고 결론 냈으면 쓸데없이 부품을 찾아 헤맸을 것이다.

고친 것: `app/core/tts/edge.py` 가 500번대면 1초·2초 쉬고 두 번 더 묻는다(`RETRY_DELAYS`).
안내도 셋으로 갈랐다 — 403 은 "새 판을 받으라", 500번대가 계속되면 "음성 서버가 응답하지 않는다",
**서버에 닿지도 못했을 때만** "인터넷 연결을 확인하라". 점검은 `voice_language_test` ⑤
(앞 몇 번만 거절하는 가짜를 끼운다. 진짜 서버가 실패해 주길 기다릴 수는 없다).

**배포 전에** `python -m pip index versions edge-tts` 로 최신 판을 확인한다 (`docs/RELEASE_CHECKLIST.md`).
([[tts-voice-must-match-text-language]] 와 같은 종류 — 인터넷이 멀쩡한데 인터넷을 탓하는 안내)

중요한 이유: CLAUDE.md 가 TTS 어댑터를 따로 두라고 한 바로 그 위험이 실제로 일어났다. 이번에는 판만 올리면 됐지만, 다음에는 edge-tts 자체가 막힐 수도 있다.
