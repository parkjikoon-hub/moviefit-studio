설치본과 개발본이 같은 포트(8765)를 쓰기 때문에, 점검 스크립트를 그냥 돌리면 **방금 고친 코드가 아니라 예전에 설치한 프로그램을 검사하고서 "통과"라고 말한다.** 가장 위험한 종류의 거짓 통과다.

무슨 일이 있었나 (2026-08-13):
기능 4건을 만들기 시작하면서 개발 서버를 띄우려 했더니 8765가 이미 쓰이고 있었다.
확인해 보니 사용자가 설치한 프로그램(v0.2.1)이 돌고 있었다
(`C:\Users\INTEL\AppData\Local\Programs\MovieFit Studio\python\python.exe`, 포트를 잡은 프로세스는
`Get-NetTCPConnection -LocalPort 8765 -State Listen` 로 찾는다).

여기서 위험한 것은 **서버가 응답한다는 사실 자체**다. `/api/health` 도 200을 돌려주고
`/` 도 화면을 준다. 점검 스크립트는 아무 불평 없이 끝까지 돌고 "전부 통과"라고 말한다.
그런데 검사한 것은 **내가 방금 고친 코드가 아니라 지난주에 설치한 프로그램**이다.

실제로 이것을 알아챈 방법: 화면을 받아 새로 넣은 문자열이 있는지 봤다.

    with urllib.request.urlopen('http://127.0.0.1:8765/') as r:
        '<button id="save-state"' in r.read().decode()   # → False (구버전이었다)

취한 조치:
1. 사용자 프로그램을 끄지 않고 **개발 서버를 다른 포트로** 띄운다. `python -m app --port 8766`
   (`app/__main__.py` 에 `--port` 인자가 원래 있다.)
2. `tests/` 의 4개 스크립트가 주소를 고정하고 있던 것을 환경변수로 바꿨다.
   기본값은 그대로 8765라 기존 사용법은 안 바뀐다.

       BASE = os.environ.get("MOVIEFIT_TEST_URL", "http://127.0.0.1:8765").rstrip("/")

   실행:  `MOVIEFIT_TEST_URL=http://127.0.0.1:8766 python tests/phase4_test.py`

앞으로 지킬 것:
- **점검을 시작하기 전에 "지금 겨냥한 서버가 내 코드를 서비스하는가"를 먼저 확인한다.**
  버전 번호만으로는 부족하다 (개발본과 설치본의 `__version__` 이 같을 수 있다).
  이번에 새로 넣은 문자열이 화면에 있는지 보는 것이 확실하다.
- 설치본을 상대로 점검하는 것 자체는 정당한 검사다 (배포 전 확인). 다만 **어느 쪽을
  검사하고 있는지 알고 하는 것**과 모르고 하는 것은 전혀 다르다.

왜 중요한가: 이 실수는 아무 오류도 내지 않고, 오히려 **통과 개수가 늘어나는 방향**으로
틀린다. 결함을 잡으라고 만든 장치가 결함을 숨기는 쪽으로 작동한다.

## 덧붙임 (2026-08-13, v0.4.0 배포) — 서버만 겨냥해서는 부족하다

설치본을 겨냥해 점검을 돌렸더니 `phase2_test` 가 "이어 붙인 오디오 파일이 실제로
있음"에서 실패했다. 제품은 멀쩡했다 — **설치본은 프로젝트를 설치 폴더 안에 만드는데
점검은 저장소의 `projects/` 를 들여다보고 있었다.**

    저장소   c:\...\capcut-studio-kit\projects\
    설치본   %LOCALAPPDATA%\Programs\MovieFit Studio\projects\

주소(`MOVIEFIT_TEST_URL`)만 바꾸면 될 것 같지만, **디스크를 직접 들여다보는 검사**는
따로 딸려 온다. 그래서 `MOVIEFIT_TEST_PROJECTS` 를 추가했다. 둘을 짝으로 바꾼다:

    set MOVIEFIT_TEST_URL=http://127.0.0.1:8765
    set MOVIEFIT_TEST_PROJECTS=%LOCALAPPDATA%\Programs\MovieFit Studio\projects

이쪽 실수는 **거짓 실패**라 그나마 낫다(거짓 통과보다 안전하다). 다만 배포 직전에
나오면 "제품이 깨졌나" 싶어 시간을 잃는다. 검사가 서버 밖의 무언가(파일·폴더)를
보고 있다면, 서버를 바꿀 때 그것도 같이 바꿔야 한다는 것을 기억할 것.

관련: 인수인계 문서 7절 "주의 2"(둘 중 하나만 켤 것)는 **화면이 안 뜬다**는 증상만 적고
있었다. 진짜 위험한 것은 화면이 잘 뜨는데 옛것이라는 쪽이다.
[[fresh-install-must-be-tested]] 와 짝을 이룬다 — 그쪽은 "개발본만 확인하면 안 된다",
이쪽은 "설치본을 개발본으로 착각하면 안 된다".
