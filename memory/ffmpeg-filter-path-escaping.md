FFmpeg 필터에 윈도우 경로를 넣을 때는 콜론 앞에 역슬래시를 **두 개** 붙여야 한다. 하나만 붙이면 실패하고, 오류 메시지가 전혀 엉뚱한 것을 가리킨다.

상황: 자막 번인(`-vf "ass=..."`)에 절대 경로를 넣자 이런 오류가 났다.

    Unable to parse "original_size" option value ... as image size

경로 문제라는 힌트가 전혀 없다. 실제 원인은 이렇다. 필터그래프 문자열이 **두 번** 해석된다.
① 필터그래프 파서가 한 겹 벗기고 ② 그다음 필터 자신의 옵션 파서가 남은 문자열을 `:` 기준으로 다시 자른다.
그래서 역슬래시 하나(`C\:/경로/자막.ass`)는 ①에서 사라져 ②가 `C`와 `/경로/...`로 쪼개 버린다.

    틀림:  ass=C\:/projects/자막.ass
    맞음:  ass=C\\:/projects/자막.ass

그런데 이걸 고쳐도 **폴더 이름에 `,` `;` `[` `]` `'` 가 들어 있으면 여전히 깨진다**
(`Trailing garbage after a filter`). 필터그래프 문법에서 이 문자들이 구분자이기 때문이다.

그래서 실제로 채택한 방법은 **경로를 아예 넘기지 않는 것**이다:
FFmpeg을 자막 파일이 있는 폴더에서 실행(`cwd`)하고 필터에는 **상대 경로**만 준다.

    cwd = 자막파일이_있는_폴더
    -vf "ass=자막.ass:fontsdir=../../../assets/fonts"

이러면 필터 문자열에 콜론도 특수문자도 들어가지 않는다.
`_테 스트, 렌더;[a]'b/자 막.ass` 같은 극단적인 폴더명에서도 정상 동작을 확인했다.
이스케이프 함수(`_escape_filter_path`)는 그대로 두되, 절대 경로가 꼭 필요한 필터를 새로 만들 때만 쓴다.

중요한 이유: 사용자가 프로젝트 이름을 "홍보영상, 최종"처럼 지으면 렌더링이 통째로 실패하는데,
오류 메시지만 봐서는 원인을 절대 못 찾는다. 앞으로 오디오 믹싱·덕킹 필터를 추가할 때도 같은 함정이 있다.

함께 조치한 것: `app/core/projects.py`의 `_slugify()`가 폴더 이름에서 `, ; [ ] '` 도 걸러 내도록 했다.
