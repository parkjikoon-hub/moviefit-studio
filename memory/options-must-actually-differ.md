선택지를 여러 개 만들었으면 **그것들이 실제로 다른 결과를 내는지 재라.** 이름만 다르고 결과가 같은 선택지는 사용자를 속이는 것이고, "만들었다"는 사실만으로는 절대 드러나지 않는다.

무슨 일이 있었나 (2026-08-14, 덕킹 세기):
사용자가 "덕킹 세기를 조절할 수 있게 해 달라"고 했다. `약하게 · 보통 · 많이` 세 단추를
만들고 압축기의 `threshold` 와 `ratio` 를 단계마다 다르게 주었다. 화면도 동작하고
저장도 되고 영상도 잘 나왔다. **그런데 실제로 재 보니:**

    약하게 → 원본의 50%
    보통   → 원본의 37%
    많이   → 원본의 32%      ← '보통'과 겨우 5%p 차이

`많이`는 **이름만 다른 가짜 선택지**였다. 귀로는 구별할 수 없다.

원인은 `release`(압축기가 놓아 주는 시간)를 세 단계 모두 400ms 로 똑같이 둔 것이었다.
짧으면 **단어와 단어 사이마다 원본이 되살아나** 평균이 올라간다. 아무리 세게 눌러도
쉬는 틈에 되돌아오므로 평균값이 바닥을 못 친다. 이 값을 함께 움직이자 벌어졌다:

    약하게 threshold .08 ratio 3  release 250 → 70%
    보통   threshold .03 ratio 12 release 400 → 37%
    많이   threshold .01 ratio 20 release 700 → 22%

## 점검에 무엇을 넣었나

`tests/ducking_test.py` 에 두 가지를 넣었다. 값만 재는 것으로는 부족했다.

- **순서**: 약하게 > 보통 > 많이 (뒤집히면 실패)
- **간격**: 단계 사이가 최소 0.05·0.03 이상 벌어져 있을 것
  ← 이것이 가짜 선택지를 잡는 검사다

## 같은 함정 — 시험 데이터가 구별 불가능한 경우

반대 방향으로도 겪었다. **제품이 아니라 시험 데이터가 같아서** 제품이 틀렸다고 오해했다.

- 영상 띠 점검에서 색 20개를 썼는데 `aqua`=`cyan`, `fuchsia`=`magenta` 로 **완전히 같은 색**이
  둘 있었다. "17초 화면이 5초로 나온다"는 엉뚱한 실패가 났다.
  → 점검 맨 앞에 **색끼리 서로 충분히 먼지 재는 검사**를 넣었다.
- 배경음 점검에서 음악을 880Hz 로 잡았는데 원본이 440Hz 였다. **880 은 440 의 2배음**이라
  음악을 하나도 안 넣어도 그 대역에 소리가 샜다. → 1500Hz 로 바꿨다.

## 왜 중요한가

세 경우 모두 **오류가 나지 않는다.** 만들어진 것은 멀쩡히 동작하고 점검도 통과한다.
"단계를 만들었다"와 "단계가 실제로 다르다"는 다르고, "값을 쟀다"와 "구별 가능한 것을
쟀다"도 다르다. 같은 뿌리: [[generated-files-need-a-different-kind-of-test]]
