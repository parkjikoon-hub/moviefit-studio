윈도우는 아이콘을 **크기별로 다른 파일에 저장**한다. 그래서 아이콘을 바꾼 뒤 크기를 바꾸면 옛 그림과 새 그림이 번갈아 나온다. `ie4uinit -show` 로는 부족하고, 저장소 파일을 전부 지우고 탐색기를 다시 켜야 한다.

무슨 일이 있었나 (2026-08-13):
아이콘을 청록에서 크림으로 바꿔 배포하고 설치까지 마쳤는데, 사용자가
"아이콘 크기를 바꿨다 되돌리면 원래대로 돌아온다. 삼각형 색이 녹색-검회색-녹색으로
자동으로 바뀐다"고 알려 왔다.

먼저 파일을 의심했지만 아니었다. `favicon.ico` 안의 **6개 크기 프레임 전부** 청록 픽셀
0개였고, 설치본 파일과 저장소 파일의 해시도 같았다. 즉 **파일은 완벽했고 화면만 옛것**이었다.

원인: `%LOCALAPPDATA%\Microsoft\Windows\Explorer\` 에 아이콘 저장소가
**15개 파일로 쪼개져 있다** — `iconcache_16.db` `_32` `_48` `_96` `_256` `_768`
`_1280` `_1920` `_2560` `_wide` `_idx` 등. 갱신 시각을 보니 16과 32만 새 시각이고
나머지는 하루 전 그대로였다. 바탕화면 아이콘 크기를 바꾸면 **읽는 파일이 바뀌므로**
어떤 크기에서는 새 그림, 어떤 크기에서는 옛 그림이 나온 것이다.

효과가 없었던 것: `ie4uinit.exe -show`. 바로가기(.lnk)를 다시 저장하는 것도 소용없었다.
저장소 파일이 그대로 있으면 윈도우는 계속 그것을 읽는다.

통한 방법:

    Stop-Process -Name explorer -Force        # 파일이 잠겨 있어 먼저 멈춰야 한다
    Start-Sleep -Seconds 3                    # 핸들이 풀릴 시간
    Remove-Item "$env:LOCALAPPDATA\Microsoft\Windows\Explorer\iconcache*.db" -Force
    Start-Process explorer.exe

15개가 전부 지워지고 몇 초 뒤 같은 시각으로 다시 만들어진다. 작업 표시줄이 2~3초
사라졌다 돌아올 뿐, 브라우저 등 다른 프로그램은 영향받지 않는다(실행 중이던 우리
프로그램도 그대로 살아 있었다). `thumbcache*.db`(42MB)는 사진 미리보기용이라 건드리지 않았다.

**결과 확인됨 (2026-08-13)**: 사용자가 아이콘 크기를 바꿔 가며 확인한 결과 색이 더 이상
번갈아 나오지 않는다고 알려 왔다. 저장소 파일이 새로 만들어진 것(간접 증거)이 아니라
**화면에서 실제로 고쳐진 것**을 확인한 것이다. 이 방법은 다음에도 그대로 쓰면 된다.

함께 고친 것: `favicon.ico` 에 **64픽셀까지만** 들어 있었다. 이 파일은 브라우저 탭뿐
아니라 **바탕화면·시작 메뉴 아이콘**으로도 쓰이는데 윈도우는 48·96·256으로 그린다.
16·32·48·64·128·256 여섯 크기를 담고, 원본도 256으로 그리도록 `tools/make_icons.py`
를 고쳤다(작게 그린 것을 키우면 뭉개진다).

교훈: **"파일을 바꿨다"와 "화면이 바뀐다"는 다른 문제다.** 배포 프로그램의 겉모습을
바꿀 때는 파일 검증(해시·픽셀)과 표시 검증(캐시)을 따로 해야 한다.
