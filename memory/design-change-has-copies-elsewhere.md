화면 색을 바꾸는 일은 CSS 한 파일로 끝나지 않는다. 그림으로 구워진 자산과 다른 폴더의 사본이 옛 색으로 남아 있다가 나중에 발각된다.

무슨 일이 있었나 (2026-08-12):
크림색 개편을 "완료"로 보고한 다음 세션에서, 사용자가 첫 화면 사진을 보내며
"박스 테두리를 진하고 굵게 하라"고 지적했다. 사진을 보니 두 가지가 더 있었다.

1. **시작 화면만 옛 규칙이었다.** 다른 화면의 바깥 상자는 진한 크림 2px인데,
   시작 화면의 `.drop-zone` 과 `[대본으로 시작하기]` 는 `--line`(#2E2A26)을 쓰고 있었다.
   거의 검정이라 상자로 읽히지 않았다. 개편할 때 작업 화면만 훑고 시작 화면을 빠뜨린 것이다.
2. **아이콘이 아직 청록이었다.** 아이콘은 CSS가 아니라 `tools/make_icons.py` 가 그려서
   PNG로 굽는다. 색 상수(TEAL)가 그 스크립트 안에 따로 박혀 있어서 CSS를 아무리 고쳐도
   바뀌지 않는다. 바탕화면 아이콘·설치 파일 아이콘·브라우저 탭에 모두 쓰이는 그림이라
   사용자가 가장 자주 보는 곳인데도 마지막까지 남아 있었다.
3. **소개 사이트가 아이콘 사본을 따로 갖고 있었다.** `landing/icons/` 는 Vercel에 따로
   배포되는 폴더라 `app/static/icons/` 를 고쳐도 따라오지 않는다.

그래서 색 체계를 바꿀 때는 이 세 곳을 반드시 함께 센다:
- CSS — 화면 전체를 훑되 **자주 안 보는 화면(시작·오류·빈 상태)** 을 따로 확인한다
- **그림을 굽는 스크립트** — `tools/make_icons.py` 처럼 색을 코드에 박아 둔 곳
- **다른 폴더의 사본** — `landing/` 처럼 따로 배포되는 곳

확인 방법: 다 고친 뒤 `grep`으로 옛 색 코드(여기서는 `2DD4BF`)를 저장소 전체에서
찾아 0건인지 본다. 그림 파일은 grep에 걸리지 않으므로 눈으로 한 장 열어 본다.

왜 중요한가: 색이 하나만 어긋나도 "덜 만든 것"처럼 보인다. 그리고 하필 남아 있던 것이
아이콘 — 사용자가 프로그램을 켜기 전에 가장 먼저 보는 그림이었다.

같이 기억할 것. 눈에 보이는 것은 반드시 발견된다.
