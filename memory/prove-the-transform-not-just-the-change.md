화면을 바꾸는 기능은 **"달라졌다"로 판정하지 말고 "의도한 변환과 일치한다"로 판정하라.** 기대 결과를 다른 방법으로 한 번 더 만들어 놓고 대조하면, 임계값을 손으로 정하지 않고도 판정할 수 있다.

무슨 일이 있었나 (2026-08-14, 화면 확대):
가로 영상을 세로 9:16 으로 자를 때 화면을 당겨 담는 기능을 만들었다. 점검을 어떻게
할지가 문제였다. 흔히 쓰는 판정 둘은 **둘 다 부족하다**:

- **"크기가 맞다"** → 확대는 출력 크기를 **일부러 그대로 둔다.** 크기로는 아무것도 못 잡는다
- **"화면이 달라졌다"** → 필터를 잘못 써서 화면이 뿌예지거나 엉뚱하게 잘려도 "달라졌다"는
  통과한다. 오류 없이 틀린 결과를 그대로 지나친다

## 무엇을 했나

**기대 결과를 다른 경로로 한 번 더 만들었다.**

    A = 확대 1.0배로 내보낸 영상
    B = 확대 2.0배로 내보낸 영상          ← 검사 대상
    C = A 의 한가운데를 잘라 두 배로 키운 것  ← 기대 결과를 따로 만든 것

그리고 **닮음(PSNR)** 을 두 번 쟀다. FFmpeg 이 `-lavfi psnr` 로 바로 내준다.

    A 대 B = 14.1   (아주 다르다 — 확대가 실제로 걸렸다는 증거)
    C 대 B = 49.5   (거의 같다  — 그 달라짐이 '가운데 확대'가 맞다는 증거)

판정은 **`C 대 B` 가 `A 대 B` 보다 크다** 하나면 된다. "PSNR 이 40 이상"처럼 손으로
고른 숫자가 필요 없다. 두 값의 **차이**를 보므로 인코딩 설정이 바뀌어도 흔들리지 않는다.

## 함정 하나 — 비교 대상에 안 커지는 것이 섞이면 안 된다

처음에 자막을 넣은 채로 쟀다면 판정이 무너졌을 것이다. 자막은 **자르기 뒤에** 새겨지므로
B 에서는 커지지 않는데, C 는 A 를 통째로 확대하므로 **글자까지 같이 커진다.** 그래서
이 비교를 할 때는 자막 글자를 비워 두었다.

→ 기대 결과를 따로 만들 때는 **파이프라인의 어느 단계까지를 흉내 내는지** 맞춰야 한다.

## 어디에 또 쓸 수 있나

앞으로 만들 화면 효과(비·눈·비눗방울·폭죽)와 강조(주변 어둡게·부분 흐림)에 그대로 쓴다.
특히 **효과 구간 바깥**은 효과 없는 영상과 **완전히 같아야** 하므로, 그때는 닮음이
`inf`(완전 일치)에 가까운지 보면 된다.
