같은 내용이 여러 곳에 필요하면 사람이 복사하지 말고 **하나에서 만들어 내야** 한다. 다만 생성기를 만들면 점검이 조용히 무력해진다 — 생성기가 만든 것을 같은 생성기로 검사하면 무엇을 삼켜도 언제나 통과하기 때문이다.

## 무슨 일이 있었나 (2026-08-13)

사용설명서가 **세 곳**에 필요해졌다.

    docs/USER_GUIDE.md      마크다운 원본
    landing/guide.html      소개 사이트(Vercel)
    app/static/guide.html   프로그램 안 (인터넷 없이 열려야 함)

손으로 복사하면 반드시 어긋난다 — 이미 [[design-change-has-copies-elsewhere]] 에서
같은 실수를 네 번 했다. 그래서 `tools/build_guide.py` 를 만들어 원본 하나에서
HTML 둘을 **만들어 내게** 했다. 바깥 부품(pip 설치)을 쓰지 않았다. 설명서가 실제로
쓰는 마크다운 문법(제목·표·목록·참고상자·`**[단추이름]**`)만 처리하면 되고,
설치 파일 크기에 영향을 주면 안 되기 때문이다.

## 여기서 새로 배운 것 — 생성기는 **점검을 무력하게 만든다**

`--check`(다시 만들어서 지금 파일과 같은지 보기)를 넣고 안심했다.
독립 검증자가 이것을 정확히 찔렀다:

> `--check` 는 동어반복이다. 생성기가 만든 것을 같은 생성기로 다시 만들어 비교한다.
> **생성기가 한 장(章)을 통째로 삼켜도 양쪽이 똑같이 삼키므로 언제나 통과한다.**
> "손으로 안 고쳤다"만 증명하지 "원본을 충실히 옮겼다"는 증명하지 못한다.

옳은 지적이다. 그래서 **원본 마크다운의 문단을 한 줄씩 HTML 본문과 대조**하는 검사를
따로 넣었다 (`tests/guide_test.py` 6-4). 비교할 때 양쪽의 빈칸과 대괄호를 없애야 한다 —
`**[X]** 를` 이 HTML에서는 `<span>X</span>를` 가 되어 빈칸이 사라지기 때문이다.

**생성기를 만들 때는 점검을 두 층으로 둔다.**
1. *동기화* 검사 — 다시 만든 것과 지금 파일이 같은가 (`--check`). 손댐을 잡는다.
2. *충실도* 검사 — **원본**의 내용이 결과물에 다 들어갔는가. 생성기 자체의 결함을 잡는다.
   1번만 있으면 생성기가 무엇을 잃어버려도 영원히 초록불이다.

## 같은 함정의 다른 얼굴들 (검증자가 찾아낸 것)

- **낱말이 문서 안에 있는지만 보는 검사.** 설명서에 `잘라내기` 가 있는지만 보고
  `index.html` 의 실제 단추 이름과 대조하지 않았다. **화면의 이름이 바뀌어도 초록불**이었다.
- **숫자를 글자로만 보는 검사.** 설명서에 "1%"가 적혀 있는지만 보고 `app.js` 의
  `NUDGE_STEP` 상수와 대조하지 않았다. 실제 값을 2%로 바꿔도 통과했다.
- **기대값을 검사 대상에게 물어보는 검사 (2차 동어반복).** `phase4_test` 는
  `/api/system/framing` 에 정답을 물어보고 그 답과 렌더 결과를 비교했다.
  `framing.py` 가 틀리면 **기대값도 같이 틀려서** 통과한다.
  → 숫자를 점검 파일에 **못박아** 두었다 (1280×720 → 9:16 잘라내기 = 404×720).
- **`id` 와 `href` 정규식만 보는 검사.** 단추가 다른 것에 가려져 있거나 숨겨져 있어도
  통과한다. → 브라우저로 **실제로 눌러** 새 탭이 열리는 것까지 본다.
- **`#RRGGBB` 만 찾는 색 검사.** `#fff`, `rgb()`, `white` 를 놓친다.
  (다만 `white-space` 같은 **속성 이름**을 색으로 오인하지 않게 앞뒤 경계를 두어야 한다:
  `(?<![-\w])white(?![-\w])`)

## 점검을 고친 뒤에는 **일부러 망가뜨려 본다**

새 검사를 넣고 통과하는 것만으로는 그 검사가 일하는지 알 수 없다. 실제로 해 봤다:

    단추 이름 '잘라내기' → '가장자리 자르기'  로 바꿈
    NUDGE_STEP 1,5 → 2,10 으로 바꿈
    → 정확히 그 두 항목만 실패했다. git checkout 으로 되돌리니 다시 전부 통과.

이 30초짜리 확인이 없으면 "점검을 늘렸다"는 말은 아무 뜻이 없다.
