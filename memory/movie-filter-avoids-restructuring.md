FFmpeg 의 `movie=` 소스 필터는 **필터그래프 안에서 파일을 연다.** 그림을 겹치려고 `-i` 를 더 붙이고 `-filter_complex` 로 갈아탈 필요가 없다 — 지금의 `-vf` 한 줄 구조를 한 군데도 안 건드리고 그림·굴절·장면 넘기기를 다 할 수 있다.

무슨 일이 있었나 (2026-08-15, 5단계 물방울·비눗방울·폭죽):
인수인계 문서가 이렇게 적어 두었다.

> 지금 렌더링은 입력이 영상 하나뿐이고 `-vf` 한 줄로 끝난다. 그림을 겹치려면 `-i` 를
> 더 붙이고 `-filter_complex` 로 옮겨야 하며, 그때 **소리 흐름(`-c:a copy`)과 자막
> 필터가 살아남는지 다시 재야 한다.**

무서운 예고였다. 소리와 자막은 이 프로그램의 핵심이고, 렌더링 명령을 통째로 바꾸는
것은 되돌리기 어려운 수술이다. **그래서 먼저 쟀다.**

## 잰 결과 — 수술이 아예 필요 없었다

| 물어본 것 | 결과 |
|---|---|
| `movie=` 가 `-vf`(단순 필터그래프) 안에서 되는가 | 됨 |
| `displace`·`overlay` 가 `enable` 을 받는가 | 됨 — 구간 밖 **다른 값 0개** |
| `movie=`+`displace`+자막(ass)+`-c:a copy` 를 한 명령으로 | 됨 — 소리·자막 다 살아남음 |
| 정지 그림 한 장으로 시간식(움직임)을 만들 수 있는가 | 됨 — `loop=loop=-1:size=1,setpts=N/(fps*TB)` |
| 그 흐름이 끝나는가 (끝없는 스트림 함정 ④) | 됨 — `overlay=...:shortest=1` 을 붙이면 **0.3초에 끝남** |

쓰는 법 세 가지:

    # 사슬 중간에서는 입력 이름을 못 적으므로 null 로 이름을 붙인다
    null[m];movie=x.png,<자 되돌리기>[a];movie=y.png,<자 되돌리기>[b];
    [m][a][b]displace=edge=smear:enable='...'

    # 움직임 — 겹치는 자리에 시간식을 쓴다 (알파가 살아 뒤가 비친다)
    movie=tile.png[i];[in][i]overlay=x='...sin(2*PI*f*t)':y='-mod(t*v\,H)'

    # 장면 넘기기 — 장면을 세로로 이어 붙이고 crop 으로 칸을 고른다 (만화책)
    movie=sheet.png,loop=loop=-1:size=1,setpts=N/(30*TB),
    crop=C:C:0:'C*floor(mod((t-시작)*30\,장면수))'[i];[in][i]overlay=...:shortest=1

## 함께 지킬 것

- **파일 이름만** 필터에 넣는다. FFmpeg 을 그림이 있는 폴더에서 실행하면 된다
  (자막이 이미 쓰는 방법). 절대 경로를 넣으면 콜론에서 깨진다
  ([[ffmpeg-filter-path-escaping]]).
- 그림 파일의 밝기는 필터 안에서 **눌린다.** 자를 되돌리지 않으면 굴절 지도가
  온 화면을 민다 ([[ffmpeg-effect-layer-traps]] ③-e).
- `loop` 로 만든 흐름은 **끝이 없다.** `shortest=1` 을 빠뜨리면 렌더가 안 끝난다
  (같은 문서 ④).

왜 중요한가: **인수인계 문서에 적힌 "이렇게 해야 한다"도 추측일 수 있다.** 이번 것은
합리적이었고 나도 그대로 믿을 뻔했다. 30분짜리 실측이 위험한 구조 변경 하나를 통째로
없앴다. 앞 문서가 "다시 재야 한다"고 적어 둔 것은 **재라는 뜻이지 고치라는 뜻이 아니다.**
