화면 기능은 이제 **코드 검토로 판정하지 않아도 된다.** 진짜 브라우저를 띄워 단추를 누르는 점검(`tests/ui_test.py`)이 있고, 화면과 서버에 나뉘어 있는 같은 계산은 `app.js` 파일을 node로 그대로 실행해 대조할 수 있다.

## 1) 브라우저를 띄워 실제로 눌러 본다

`docs/ROADMAP.md` 의 Phase 1·3에는 "**코드 검토로만 판정**"이 여러 항목 달려 있다.
브라우저 자동화가 없었기 때문이다. 2026-08-13에 개발 전용으로 설치했다:

    python -m pip install playwright
    python -m playwright install chromium

`requirements.txt` 에는 **넣지 않았다.** 프로그램 실행에 필요한 것이 아니라 개발자가
점검할 때만 쓰는 도구이고, 설치 파일 크기에 영향을 주면 안 되기 때문이다.

이것으로 실제로 확인한 것들 (수치는 `tests/ui_test.py` 출력):
- `[↑]`를 누르니 자막 세로 위치가 80.0 → 79.0 으로 **정확히 1%** 움직였다
- `Shift`와 함께 `[←]`를 누르니 51.0 → 46.0 으로 **5%** 움직였다
- 화면에 그려진 화면비 틀의 너비 404픽셀이 서버 계산 404픽셀과 **같았다**
- 틀을 마우스로 120픽셀 끌자 잘라낼 자리가 50% → 67.29% 로 바뀌고 옆의 막대도 따라왔다
- `[저장됨]`을 누르자 **디스크의 저장 시각이 실제로 바뀌었다**

### 걸림돌 두 가지 (다음에 또 만난다)
- **첫 실행 안내 창(`#coach`)이 클릭을 가로막는다.** 새 브라우저는 localStorage가 비어
  있어 안내가 뜬다. Playwright는 "`<div id="coach">` intercepts pointer events" 라는
  오류를 낸다. 화면을 연 직후 닫아야 한다 (`ui_test.py` 의 `dismiss_coach()`).
- 영상 크기를 읽기 전에는 화면비 틀이 그려지지 않는다.
  `page.wait_for_function("document.querySelector('#player').videoWidth > 0")` 로 기다린다.

## 2) 화면과 서버에 같은 계산이 나뉘어 있을 때

출력 화면비 계산은 서버(`app/core/framing.py`)와 화면(`app.js`)에 **둘 다** 있다.
미리보기 틀은 마우스를 끄는 동안 즉시 다시 그려야 해서 서버에 물어볼 수 없기 때문이다.
두 곳이 어긋나면 "미리보기와 결과물이 다르다"는 최악의 결함이 된다.

**계산식을 테스트에 베껴 두면 안 된다.** 베낀 쪽만 맞고 진짜 화면은 틀린 상태를 못 잡는다.
그래서 `app.js` **파일 자체**를 node로 실행한다. 브라우저에만 있는 것들은 "무엇을 물어봐도
자기 자신을 돌려주는 가짜 요소"(`Proxy`) 하나로 전부 흉내 낸다 — `tests/phase4_test.py` 2절.
이렇게 240가지 경우를 대조했다.

### 반올림 규칙을 먼저 통일해야 한다
파이썬 `round()` 는 0.5를 짝수 쪽으로 보내고(606.5 → 606) 자바스크립트 `Math.round` 는
언제나 위로 올린다(606.5 → 607). 같은 계산이라고 믿었는데 1픽셀씩 어긋난다.
양쪽 모두 `floor(v + 0.5)` 로 못 박았다 (`framing._round()` ↔ `app.js` 의 `frRound`).

## 3) "자막이 있다"를 밝은 픽셀 수로 세면 안 된다

화면비를 바꿔도 자막이 살아 있는지 확인하려고 결과 영상의 밝은 픽셀을 셌더니 10만 개가
나왔다. 통과처럼 보이지만 **영상 배경이 원래 밝았다.** 자막이 하나도 없어도 통과한다.
[[tts-silence-padding]] 에 적힌 동어반복 검증과 같은 함정이다.

고친 방법: **같은 설정으로 자막 글만 비운 영상을 한 번 더 만들어** 같은 시각의 프레임을
비교한다. 두 영상의 차이는 오직 자막이므로 늘어난 밝은 픽셀이 곧 글자다.
(자막 있음 103,200 − 자막 없음 100,640 = 글자 2,560개)

왜 중요한가: 이 프로젝트에서 발견된 결함 대부분은 "코드는 그렇게 되어 있는데 화면에서는
안 되던 것"이었다. 이제 그것을 기계가 잡을 수 있다. 다만 **보기 좋은지는 여전히 사용자만
안다** — 자동 점검이 대신해 주지 않는다.

소용없다. [[design-change-has-copies-elsewhere]] — 같은 것이 여러 곳에 사본으로 있는 문제.
