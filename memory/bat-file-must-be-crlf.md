윈도우 배치 파일(.bat)은 줄바꿈이 반드시 CRLF여야 한다. LF로 저장하면 cmd가 각 줄의 앞글자를 잘라먹으며 엉뚱한 오류를 뱉는다.

상황: run.bat을 실행하자 이런 오류가 줄줄이 나왔다.
    'launcher'은(는) 내부 또는 외부 명령이 아닙니다
    'itle'은(는) 내부 또는 외부 명령이 아닙니다
    'ch.py'은(는) 내부 또는 외부 명령이 아닙니다
'title' → 'itle', 'launch.py' → 'ch.py' 처럼 **앞부분이 잘린 조각**이 명령으로 해석되는 것이 이 문제의
지문이다. cmd는 한 줄을 실행한 뒤 바이트 위치를 계산해 다음 줄로 넘어가는데, CR이 없으면
한 칸씩 어긋나 줄 중간에 착지한다.

처음에 "cmd가 한글을 못 읽어서 그렇다"고 잘못 진단했다. 한글은 원인이 아니었다.
(한글이 든 줄에서 처음 터졌을 뿐이다.) 조각난 영단어가 보이면 인코딩이 아니라 줄바꿈을 먼저 의심할 것.

해결: 파일을 쓴 뒤 바이트 단위로 변환한다.
    raw.replace(b"\r\n", b"\n").replace(b"\n", b"\r\n")
Write 도구는 LF로 저장하므로, .bat 파일을 새로 만들거나 고칠 때마다 이 변환을 반드시 거쳐야 한다.

부수적으로 확인된 것: run.bat 안에 한글을 넣지 않고 안내 문구를 tools/launch.py(파이썬)로 옮긴
구조는 그대로 두었다. chcp 65001과 파일 인코딩이 엇갈릴 여지를 아예 없애 주기 때문이다.
