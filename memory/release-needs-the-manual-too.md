공개 배포 절차에 **사용설명서 점검**이 빠져 있었다. 기능은 완성되고 점검 813개가 통과해도, 설명서에 그 장이 없으면 내려받은 사람은 기능이 있는 줄도 모른다. 그리고 옛 설명서의 "이건 안 됩니다" 문구가 조용히 거짓말이 된다.

무슨 일이 있었나 (2026-08-15, v0.6.0 배포):

인수인계 6-3절의 배포 순서는 이랬다 — ① 버전 올리기 ② 릴리스 노트 ③ exe 빌드
④ 빈 환경 설치 시험 ⑤ GitHub 릴리스 ⑥ Vercel. **설명서가 없다.**

그대로 따랐다면 화면 효과 16종이 들어간 v0.6.0 을 내보내면서:

- 사용설명서(v4.0, 대상 버전 0.5.0)에는 화면 효과가 **한 줄도 없고**
- 1장에 "영상을 자르거나 붙이거나 **색을 보정하는** 편집 기능은 없습니다" 가 남아 있고
  (따뜻하게·차갑게·빈티지·흑백이 이미 들어와 있었다)
- 소개 사이트 첫 페이지 "만들지 않는 것" 에 "컷 편집·전환·**필터**·스티커" 가 남아 있고
- 같은 페이지에 "자동 점검 **123개** 항목" (당시 실제 21개 묶음 800여 개)

가 그대로 공개될 뻔했다. 이 넷은 **점검이 절대 못 잡는다.** 코드와 설명서를 맞대 보는
`tests/guide_test.py` 조차 "설명서에 적힌 것이 코드와 맞는가"만 묻지, **"코드에 있는 것이
설명서에 있는가"는 묻지 않기 때문이다.** 없는 장은 아무 검사도 걸리지 않는다.

## 장 번호를 미는 일은 손으로 하지 말 것

새 장을 중간에 끼우면 뒤의 장이 전부 밀린다. 이번에는 9장을 넣어 옛 9~19장이
10~20장이 되었다. 손으로 고치면 **소절 번호(`### 9-1`)나 상호참조(`13장 참고`) 중
하나를 반드시 빠뜨린다.** 스크립트로 큰 수부터 내려오며 바꾸고(작은 수부터 하면
방금 만든 번호를 다시 바꾼다), 바꾼 뒤 이 둘을 검사한다:

- `### N-M` 의 N 이 그 줄이 속한 장 번호와 같은가 (어긋난 곳 0건이어야 한다)
- `N장` 참조가 가리키는 장의 제목이 뜻과 맞는가

주의: `사진 30장` 처럼 **장(章)이 아닌 '장'** 이 있다. 미는 범위(9~19)를 벗어나면
저절로 안 건드려지지만, 범위 안의 숫자를 쓰는 문장이 있으면 먼저 확인해야 한다.

설명서 HTML 둘(`app/static/guide.html`·`landing/guide.html`)은 `tools/build_guide.py`
가 `docs/USER_GUIDE.md` 하나에서 만들어 낸다. 마크다운만 고치고 생성기를 돌린 뒤,
**두 HTML에 새 장이 실제로 들어갔는지 파이썬으로 확인한다**
([[powershell-reads-korean-as-cp949]] — PowerShell 로 한글을 찾으면 조용히 실패한다).

왜 중요한가: [[fresh-install-must-be-tested]] 와 같은 뿌리다. 그쪽은 "내 컴퓨터에서
도는 것"과 "남의 컴퓨터에서 도는 것"의 차이고, 이쪽은 **"만든 것"과 "남이 찾을 수
있는 것"의 차이**다. 둘 다 개발 컴퓨터 안에서는 아무 증상이 없다.
